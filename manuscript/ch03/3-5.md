# 3.5 localhost:8000의 의미 — 지금 이게 왜 나한테만 보이는가

터미널에서 `uvicorn main:app --reload`를 실행하는 순간, 여러분의 컴퓨터에서는 이런 일이 일어납니다.

**여러분의 노트북이 서버가 됩니다.**

2장에서 말했죠 — 서버는 "요청받으면 응답하는 컴퓨터"라고. uvicorn이라는 프로그램이 여러분 컴퓨터 안에서 대기하면서, 브라우저가 요청하면 초대장을 응답해주고 있는 겁니다. 다만 아주 제한적인 서버입니다.

## 주소를 뜯어봅시다

```
http://localhost:8000
        ───┬───  ─┬─
           │      └─ 포트(port): 한 컴퓨터 안의 "창구 번호"
           └─ "이 컴퓨터 자신"이라는 뜻
```

- **localhost** — "지금 이 컴퓨터"를 가리키는 예약된 이름입니다. 어느 컴퓨터에서 치든 자기 자신을 가리킵니다. 그래서 이 주소를 친구에게 보내면 친구는 **자기 폰 안**을 뒤지게 되고, 당연히 아무것도 없습니다.
- **8000 (포트)** — 한 컴퓨터 안에는 여러 프로그램이 동시에 서버 노릇을 할 수 있어서, 창구 번호로 구분합니다. uvicorn이 8000번 창구에서 대기 중인 겁니다. 은행 창구 번호라고 생각하면 됩니다.

## 지금 상태의 3가지 한계

| 한계 | 이유 | 해결되는 장 |
|---|---|---|
| 나만 접속 가능 | localhost = 내 컴퓨터 | 5장 (Vercel) |
| 노트북 덮으면 끝 | 서버가 꺼짐 | 5장 (Vercel) |
| 껐다 켜면 메시지 증발 | 메모리 저장 | 7장 (Neon) |

이 표가 사실상 이 책의 남은 목차입니다. 우리가 뭘 하러 가는지 이제 정확히 보이시죠.

## --reload의 정체 (보너스)

실행 명령 끝의 `--reload`는 "코드가 바뀌면 서버를 자동으로 다시 시작해줘"라는 옵션입니다. Claude가 코드를 고칠 때마다 여러분이 서버를 껐다 켤 필요가 없도록요. 개발할 때만 쓰는 편의 기능이고, 배포된 서버에는 필요 없는 옵션입니다.

> **🚧 자주 막히는 지점**
>
> - *"주소를 폰으로 열어봤는데 안 돼요."* — 정상입니다. 그게 바로 localhost의 뜻입니다. 폰에서 열리게 만드는 게 5장입니다.
> - *"8000이 아니라 다른 숫자로 떠요."* — 문제없습니다. 8000번 창구가 이미 사용 중이면 다른 번호를 쓰기도 합니다. 터미널에 표시된 주소를 그대로 열면 됩니다.
