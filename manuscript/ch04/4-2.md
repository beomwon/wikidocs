# 4.2 Git 몰라도 되는 최소한의 Git — add, commit, push 세 동작

Git 책은 500페이지가 넘습니다. 우리는 세 단어만 배웁니다. 이 세 단어면 이 책을 완주할 수 있고, 사실 많은 현업 개발자도 하루의 90%는 이 세 동작만 합니다.

## 택배 비유 하나로 끝내기

코드를 GitHub에 보내는 건 택배를 보내는 것과 같습니다.

```
add    →  상자에 물건 담기       "이 파일들 보낼 거야"
commit →  상자 봉하고 송장 쓰기   "8/1: 방명록 기능 추가" (기록이 남음)
push   →  택배 발송             GitHub으로 실제 전송
```

- **add** — 이번에 보낼 파일을 고르는 단계입니다. 보통 "바뀐 거 전부"를 담습니다.
- **commit(커밋)** — 상자를 봉하면서 **한 줄 메모(커밋 메시지)**를 남기는 단계입니다. 이 메모가 나중에 "되돌아갈 수 있는 저장 시점"의 이름표가 됩니다. 게임의 세이브 포인트에 이름 붙이기라고 생각하세요.
- **push(푸시)** — 봉한 상자들을 GitHub으로 실제로 보내는 단계입니다. **5장부터는 push가 곧 "배포 버튼"이 됩니다.** 이 단어는 특별히 기억해 두세요.

## 순서가 중요합니다

담지 않은 물건은 봉해지지 않고(add 안 하면 commit에 안 들어감), 봉하지 않은 상자는 발송되지 않습니다(commit 안 하면 push할 게 없음). 뭔가 "분명히 고쳤는데 GitHub에 반영이 안 돼요"의 90%는 이 순서 어딘가가 빠진 겁니다.

## 직접 외울 필요는 없습니다

실제 명령 실행은 Claude Code에게 시키면 됩니다.

> **Claude에게 이렇게 시키세요**
>
> ```
> 이 프로젝트를 git으로 관리하기 시작하고 싶어.
> git 초기 설정(내 이름/이메일 등록 포함)을 해주고,
> 지금까지의 코드를 "초대장 첫 완성"이라는 메시지로 커밋해줘.
> 아직 GitHub에는 올리지 마.
> ```

Claude가 `git init`(이 폴더를 Git 관리 대상으로 지정), `git add .`, `git commit -m "초대장 첫 완성"`을 실행해 줄 겁니다. 뭘 했는지 설명도 해줄 거고요.

**단, 세 단어의 의미는 여러분이 알고 있어야 합니다.** AI가 "커밋할까요?"라고 물을 때 그게 뭔지 알아야 "응" 할 수 있으니까요. 이 책의 원칙 그대로입니다 — 실행은 AI가, 판단은 여러분이.

> **자주 막히는 지점**
>
> - *"커밋 메시지를 뭐라고 써야 해요?"* — "무엇을 바꿨는지" 한 줄이면 됩니다. "방명록 추가", "디자인 수정". 잘 쓰려고 고민하지 마세요. 미래의 내가 알아볼 정도면 충분합니다.
> - *"얼마나 자주 커밋해요?"* — "잘 되는 상태"가 될 때마다. 특히 **AI에게 큰 수정을 시키기 직전**에 커밋해 두세요. 망가지면 돌아올 세이브 포인트가 됩니다. 이게 바이브코더의 생존 습관 1번입니다.
