# 4.1 GitHub이 뭐길래 다들 쓰라고 하는가

## Git과 GitHub은 다른 것입니다

먼저 헷갈리는 것부터 정리합니다.

- **Git** — 내 컴퓨터에서 도는 **버전 관리 프로그램**. 코드의 "저장 시점"을 사진 찍듯 남겨두는 도구입니다.
- **GitHub** — 그 저장 시점들을 올려두는 **인터넷 보관소**(웹사이트). Git으로 찍은 사진첩을 구름 위에 올려두는 곳입니다.

이름이 비슷해서 그렇지, "한글(프로그램)"과 "구글 드라이브(보관소)"의 관계와 같습니다.

## 우리에게 GitHub이 필요한 이유 세 가지

**① 배포의 출발점이라서 (이 책의 핵심 이유)**

다음 장에서 쓸 Vercel은 이렇게 일합니다: "네 GitHub 저장소를 알려줘. 내가 지켜보고 있다가, 새 코드가 올라올 때마다 자동으로 배포해줄게." 즉 GitHub은 **내 컴퓨터와 서버 사이의 공식 전달 창구**입니다. 이 구조 덕분에 우리는 서버에 접속해 파일을 옮기는 일 따위를 평생 안 해도 됩니다.

**② 백업이라서**

노트북을 잃어버려도, 실수로 폴더를 날려도, GitHub에 올려둔 코드는 남아 있습니다.

**③ 되돌리기가 돼서**

바이브코딩의 고질병: "AI가 뭔가 고치다가 잘 되던 걸 망가뜨렸는데, 아까로 돌아가고 싶다." Git은 저장 시점마다 사진을 찍어두므로, 언제든 "어제 저녁 상태로 되돌려줘"가 가능합니다. AI에게 과감하게 시킬 수 있는 배짱이 여기서 나옵니다.

## 준비: GitHub 가입

[github.com](https://github.com)에서 무료로 가입하세요. 이메일만 있으면 됩니다. 아이디는 나중에 저장소 주소에 들어가니(`github.com/아이디/저장소이름`) 너무 장난스럽지 않은 걸 권합니다.

가입 후 화면에서 뭘 해야 할지는 몰라도 됩니다. 웹사이트에서 클릭할 일은 거의 없고, 다음 절부터 터미널과 Claude가 다 합니다.

> **🚧 자주 막히는 지점**
>
> *"저장소(repository)가 뭐예요?"* — **저장소(레포)**는 GitHub 위의 "프로젝트 하나당 폴더 하나"입니다. 우리 초대장 프로젝트 = 저장소 하나. 다음에 다른 걸 만들면 = 새 저장소. 그게 전부입니다.

다음 절에서 Git의 핵심 동작 세 가지를 — 딱 세 가지만 — 배웁니다.
