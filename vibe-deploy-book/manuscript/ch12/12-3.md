# 12.3 당신은 이제 물어볼 수 있는 사람이다 — 다음에 만들 것들

## 이 책이 진짜로 준 것

이 책의 목표는 초대장이 아니었습니다. 1장에서 말한 대로 — **어휘**였습니다. 배포, 서버리스, 환경변수, DNS, HTTPS. 이 단어들을 아는 사람은 AI에게 무엇이든 시킬 수 있습니다. 여러분이 갖게 된 건 완성품 하나가 아니라, **앞으로 뭐든 완성까지 끌고 갈 수 있는 질문 능력**입니다.

10.3절의 만능 틀에 아이디어만 갈아 끼우세요. 만들고 → push → Import → 서브도메인. 놀이터는 이미 지어져 있습니다.

## 더 알아보기 — 이 책 밖의 세계 (짧게)

이 책은 의도적으로 한 가지 경로(FastAPI + Vercel + Neon + 호스팅케이알)만 팠습니다. 세상에는 대안이 많고, 언젠가 이 이름들을 만나게 될 겁니다. 미리 한 줄씩만 소개합니다.

- **Render / Railway / Fly.io** — "항상 켜져 있는 서버" 방식의 배포 서비스. 6.4절의 못 하는 일들(웹소켓, 백그라운드 작업)이 필요해지면 이쪽을 알아볼 때입니다.
- **Supabase** — Neon처럼 DB를 주면서 로그인, 파일 저장까지 묶어주는 서비스. "회원가입 기능"이 필요해지는 날 유력 후보.
- **AWS / GCP / Azure** — 클라우드의 원류이자 종합 백화점. 자유도는 무한대, 진입장벽과 과금 방식의 난이도도 무한대(11.2절 유형 ②). 취업·이직용 기술로는 가치가 크지만, 개인 프로젝트에 급할 건 없습니다.
- **GitHub Actions** — push했을 때 배포 말고도 온갖 자동화(테스트, 알림, 정기 작업)를 걸 수 있는 GitHub의 자동화 도구. "push하면 자동으로 OO되게 하고 싶어"라는 생각이 들면 그게 신호입니다.

어느 것이든, 접근법은 이 책에서 한 그대로입니다: **AI에게 "나 이거 처음이야, 단계별로 알려줘. 무료 플랜은 멈추는 방식이야 과금 방식이야?"라고 물어보며 시작하기.**

## 마지막 당부 세 가지

1. **도메인 갱신 알림, 다시 한번 확인.** (책에서 세 번째 말하는 겁니다. 그만큼 중요합니다.)
2. **비밀(접속 주소, API 키)은 코드에 쓰지 않는다** — 이 습관 하나가 여러분을 사고로부터 지킵니다.
3. **막히면 에러 원문을 통째로.** 3.6절의 황금 템플릿은 평생 갑니다.
