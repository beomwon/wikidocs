## A. 카카오맵

### A-1. 가입

- 사이트: [developers.kakao.com](https://developers.kakao.com) (카카오디벨로퍼스)
- 카카오계정 필수. 우측 상단 `로그인` → 카카오계정으로 로그인
- 로그인만으로 끝나지 않는다. 이어서 `회원가입` 화면에서 **약관 필수 항목 동의 + 개발자 이름 입력** → 회원가입 완료
- 출처: developers.kakao.com/docs/ko/tutorial/start

### A-2. 앱 만들기

- 경로: `내 애플리케이션` → `애플리케이션 추가하기` → 팝업에 입력 → `저장`
- 앱 목록 주소: [developers.kakao.com/console/app](https://developers.kakao.com/console/app)
- 입력 항목 (화면 표기 그대로)
  - **앱 이름** (필수)
  - **회사명** (필수) — 서비스의 상호, 법인 또는 단체명. 개인이면 본인 이름이나 모임 이름을 적으면 된다
  - **카테고리** (필수)
  - **앱 아이콘** (선택) — 250KB 미만, 128×128 이하 권장

### A-3. 앱 키 4종

| 키 이름 | 용도 |
|---|---|
| REST API 키 | 서버에서 REST 방식으로 카카오 API 호출할 때 |
| **JavaScript 키** | **Kakao SDK for JavaScript 사용 시 — 지도에 쓰는 것이 이것** |
| 네이티브 앱 키 | Android, iOS 앱 |
| 어드민 키 | 민감한 설정·자원 접근용 |

- 지도는 **JavaScript 키**. 공식 지도 가이드 원문: "JavaScript 키를 확인하고 복사하여, 지도 API의 appkey로 사용합니다."
- **REST API 키를 넣으면 에러가 난다.** 초보자가 가장 많이 하는 실수 → 반드시 경고할 것

### A-4. 카카오맵 사용 설정 (2026-07-21부터 바뀐 부분)

- 경로: `앱` > `제품 설정` > `카카오맵` > `사용 설정`의 `상태`를 **ON**
- **2026년 7월 21일부터 별도 신청이나 관리자 심사 없이** 이 스위치만 켜면 쓸 수 있다 (그 전에는 심사가 있었음)
- 예전 자료에 나오는 "카카오맵 사용 신청 후 승인 대기" 설명은 지금은 맞지 않는다
- 출처: devtalk.kakao.com/t/api-4/150764

### A-5. 도메인 등록 (필수)

- 공식 가이드 원문: **"등록된 사이트 도메인에서만 지도API를 사용할 수 있기 때문에 반드시 등록해주세요."**
- 경로 (현재 공식 문서 표기): `앱` > `앱 설정` > `앱` > `플랫폼 키` > `JavaScript 키` > **`JavaScript SDK 도메인`**
- 형식: `https://example.com` 처럼 **도메인만**. 경로는 자동으로 잘린다 (`https://www.example.com/mypage` 를 넣으면 `https://example.com` 으로 등록됨)
- **최대 10개**까지 등록 가능. 와일드카드 사용 가능
- 등록해야 할 것: 내 도메인, `www.` 붙은 형태, Vercel이 준 `*.vercel.app` 주소, 그리고 로컬 테스트용 주소
- 로컬 테스트: `http://localhost:8000` 처럼 **포트까지 포함해서** 한 줄 추가하면 동작한다 (다만 이건 공식 문서 근거가 아니라 개발자 사례 기준 — 원고에서 "공식 안내는 없지만 실제로는 이렇게 하면 됩니다" 식으로 쓸 것)

### A-6. SDK 로드

기본형 (공식 문서 원문):

```
<script type="text/javascript" src="//dapi.kakao.com/v2/maps/sdk.js?appkey=발급받은_JavaScript_키"></script>
```

라이브러리 포함형:

```
<script type="text/javascript" src="//dapi.kakao.com/v2/maps/sdk.js?appkey=발급받은_JavaScript_키&libraries=services"></script>
```

- `libraries`에 넣을 수 있는 값 3종: `services`(장소 검색·주소↔좌표 변환), `clusterer`(마커 묶기), `drawing`(그리기)
- 공식 문서: [apis.map.kakao.com/web/guide](https://apis.map.kakao.com/web/guide/)
- `autoload=false`는 **쓰지 말 것.** 실무에서 쓰이긴 하나 공식 문서에 설명이 없어 이 책에서는 다루지 않는다

### A-7. 무료 쿼터 (2026-07-21부터 바뀐 부분 — 매우 중요)

- **개발자 계정 기준 첫 번째로 활성화한 앱에만 무료 쿼터를 제공한다.** 두 번째 활성화 앱부터는 비즈월렛 연결 + 유료 설정을 해야 쓸 수 있다
  - → **원고에 "실습용 앱을 여러 개 만들지 말고 하나를 만들어 계속 쓰세요"를 반드시 넣을 것**
- 무료 쿼터 (첫 번째 활성화 앱 기준)

| 구분 | 일 쿼터 |
|---|---|
| 지도 Web(JavaScript) SDK | 300,000건 |
| 로컬 REST API (주소↔좌표 변환, 장소 검색 등) | 각 100,000건 |
| 정적 지도 조회 | 1,000건 |
| 월 쿼터 (전체 API 합산) | 3,000,000건 |

- 초과하면 **429 Too Many Requests** 에러
- 초대장 규모에서는 하루 30만 건을 넘길 일이 없다는 감각을 주되, 수치는 "발급 화면·공식 안내에서 확인하세요"를 덧붙일 것
- 출처: developers.kakao.com/docs/ko/getting-started/quota

### A-8. 지도가 회색으로만 뜨는 대표 원인 (콘솔에 401이 함께 찍히는 경우가 많음)

1. **도메인 미등록/불일치** — 가장 흔하다
2. **키 종류 오류** — JavaScript 키가 아니라 REST API 키를 넣음
3. **카카오맵 사용 설정이 OFF** — `제품 설정` > `카카오맵` 상태가 ON이 아님
4. **프로토콜/포트 불일치** — `http`로 접속하는데 `https`만 등록, `localhost:8000`의 포트 누락
5. **서브도메인 누락** — `www.` 유무
6. **쿼터 소진** (429). 두 번째 앱이면 무료 쿼터 자체가 없음
7. **지도를 담을 영역에 높이가 없음** — 키 문제가 아니라 화면 문제인데 증상이 똑같이 회색이다. 비개발자에게 특히 안내할 가치가 있음

## B. 공공데이터포털 기상청 단기예보

### B-1. 가입

- 사이트: [data.go.kr](https://www.data.go.kr)
- **본인인증 필수**
- 가입 단계 (화면 표기 그대로): `STEP 1 가입확인 및 회원구분` → `STEP 2 약관 동의` → `STEP 3 정보입력`(아이디/비밀번호/이름/이메일/휴대폰번호) → `STEP 4 본인인증` → `STEP 5 기업정보 진위확인`(기업회원만)

- 개인은 **일반회원**(만 14세 이상 내국인)

### B-3. 승인과 대기

- **개발계정·운영계정 모두 자동승인**이다 (상세 페이지의 "심의여부"에 명시). 신청과 동시에 승인된다
- 다만 **발급 직후 호출하면 에러가 날 수 있다.** 포털에서 발급된 키가 제공기관(기상청) 서버에 동기화되기까지 시간이 걸리기 때문이다
  - 이때 나오는 에러: `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` 또는 `SERVICE_ACCESS_DENIED_ERROR`
  - **정확한 대기 시간은 공식 문서에 명시가 없다.** "최대 한 시간쯤 걸릴 수 있으니 기다렸다 다시 해보세요" 정도로 쓸 것. 시간을 단정하지 말 것

### B-4. 인증키 위치와 Encoding / Decoding

- 경로: 우측 상단 `마이페이지` → 좌측 `데이터활용` → `Open API` → `활용신청 현황` → 해당 API 클릭
- 상세 화면 아래에 **일반 인증키(Encoding)** 와 **일반 인증키(Decoding)** 두 개가 나란히 있다
- 차이
  - **Decoding 키** = 원본. `+`, `/`, `=` 같은 특수문자가 그대로 들어 있다
  - **Encoding 키** = 그 원본을 URL용으로 바꾼 것. `+` → `%2B`, `/` → `%2F`, `=` → `%3D`
- 어느 쪽을 쓰나
  - 주소창이나 `curl`처럼 **URL에 직접 붙여 넣을 때** → **Encoding 키**
  - 코드에서 라이브러리가 파라미터를 알아서 인코딩해 줄 때 (파이썬 `requests`의 `params=` 등) → **Decoding 키**. Encoding 키를 넣으면 두 번 인코딩되어 `%2B`가 `%252B`가 되고 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`가 난다
- **공식 규정 문서는 없다.** 실무 관행이다. 원고에는 "한쪽으로 안 되면 다른 쪽으로 바꿔 넣어보라"는 현실적 조언을 함께 쓸 것

### B-5. 오퍼레이션과 파라미터

제공 오퍼레이션 4종: `getUltraSrtNcst`(초단기실황), `getUltraSrtFcst`(초단기예보), **`getVilageFcst`(단기예보 — 이 책에서 쓰는 것)**, `getFcstVersion`(예보버전)

- `getVilageFcst` 철자 주의. `getVillageFcst`처럼 `l`을 하나 더 쓰면 `NO_OPENAPI_SERVICE_ERROR`가 난다

요청 파라미터

| 이름 | 필수 | 설명 |
|---|---|---|
| `serviceKey` | 필수 | 공공데이터포털에서 받은 인증키 |
| `pageNo` | 필수 | 페이지 번호 |
| `numOfRows` | 필수 | 한 페이지 결과 수 |
| `dataType` | 선택 | 요청자료형식 (XML/JSON). JSON 권장 |
| `base_date` | 필수 | 발표일자 (YYYYMMDD) |
| `base_time` | 필수 | 발표시각 (HHMM, 정시) |
| `nx` | 필수 | 예보지점 X 좌표 |
| `ny` | 필수 | 예보지점 Y 좌표 |

- 포털 문서에는 `ServiceKey`(대문자 S)로 적혀 있지만 실제 호출은 `serviceKey`(소문자 s)로 하는 것이 통용된다. 이 불일치가 실제 오류 원인이 되므로 짚어줄 것

### B-6. base_time

- 1일 8회 발표: `0200`, `0500`, `0800`, `1100`, `1400`, `1700`, `2000`, `2300`
- 예보 기간: 02·05·08·11·14시 발표분은 글피 자정까지, 17·20·23시 발표분은 그글피 자정까지 (1시간 간격)
- API로 실제 받아볼 수 있는 시각은 발표시각보다 조금 뒤다. **발표 직후에는 아직 데이터가 없으니 10분 이상, 넉넉히는 15분쯤 지난 뒤에 호출**하라고 쓸 것 (정확한 +10분 표는 2차 인용이므로 단정하지 말 것)
- `base_date`는 최근 3일까지만 조회 가능

### B-7. 격자 좌표

- 이 API는 **위도·경도를 받지 않는다.** 전국을 5km × 5km 격자로 나눈 `nx`, `ny` 값만 받는다
- **공식 엑셀 파일이 있다.** data.go.kr 상세 페이지의 `참고문서`에 있는 활용가이드 압축파일 안에 읍·면·동별 격자 좌표 엑셀이 들어 있다
  - 2026년 7월 기준 파일명: `기상청41_단기예보 조회서비스_오픈API활용가이드_2607.zip` (파일명에 날짜가 들어가므로 바뀔 수 있다고 안내할 것)
  - 압축을 풀면 활용가이드 문서 + 격자 좌표 엑셀. 엑셀에서 내 지역을 찾아 **`격자 X`, `격자 Y`** 열의 값을 그대로 `nx`, `ny`에 넣으면 된다
- **비개발자에게는 좌표 변환 공식을 구현하게 하지 말고 이 엑셀에서 찾아 쓰게 할 것.** 모임 장소는 한 곳이므로 평생 한 번만 찾으면 된다

### B-8. 응답 코드

| 코드 | 뜻 | 값 |
|---|---|---|
| `TMP` | 1시간 기온 | 섭씨 숫자 |
| `POP` | 강수확률 | 0~100 (%) |
| `PTY` | 강수형태 | 0 없음 / 1 비 / 2 비·눈 / 3 눈 / 4 소나기 |
| `SKY` | 하늘상태 | 1 맑음 / 3 구름많음 / 4 흐림 |

- **SKY 주의**: 공식 코드표에는 2(구름조금)도 있지만 단기예보 응답에서는 실제로 **1, 3, 4 세 값만 나온다.** 원고에는 세 값만 나온다고 쓰되, 2도 대비해두라고 프롬프트에 넣을 것
- 아이콘 결정 규칙 (실무 표준): **PTY가 0이면 SKY를 보고 표시하고, 0이 아니면 PTY를 보고 표시한다**
- 함께 자주 쓰는 것: `TMN`(일 최저기온, 0200 발표분에 주로 포함), `TMX`(일 최고기온, 1100 이후 발표분), `REH`(습도), `WSD`(풍속), `PCP`(1시간 강수량), `SNO`(1시간 신적설)

### B-9. 에러 코드

| 코드 | 이름 | 실제 원인 |
|---|---|---|
| 01 | `APPLICATION_ERROR` | base_date / base_time을 잘못 넣음. 아직 발표되지 않은 시각을 요청한 경우가 흔하다 |
| 02 | `DB_ERROR` | 기상청 쪽 오류. 내 잘못이 아니다 |
| 03 | `NODATA_ERROR` | 요청한 격자에 데이터가 없다. nx/ny 오타이거나 국내 범위를 벗어남 |
| 04 | `HTTP_ERROR` | 제공기관 서버 응답 없음 |
| 05 | `SERVICETIME_OUT` | 일시적. 다시 시도 |
| 10 | `INVALID_REQUEST_PARAMETER_ERROR` | 파라미터 값이 이상하다. base_time에 `0230`처럼 정시가 아닌 값을 넣은 경우 등 |
| 11 | `NO_MANDATORY_REQUEST_PARAMETERS_ERROR` | 필수 파라미터 누락 |
| 12 | `NO_OPENAPI_SERVICE_ERROR` | 주소가 틀렸거나 오퍼레이션명 오타 (`getVillageFcst`) |
| 20 | `SERVICE_ACCESS_DENIED_ERROR` | 발급한 키가 기상청 쪽에 아직 동기화되지 않음. 시간을 두고 재시도 |
| 21 | `TEMPORARILY_DISABLE_THE_SERVICEKEY_ERROR` | 키가 일시 중지됨 |
| 22 | `LIMITED_NUMBER_OF_SERVICE_REQUESTS_EXCEEDS_ERROR` | **일일 요청 횟수 초과** |
| 30 | `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` | 등록되지 않은 키. **실제로는 키가 틀린 게 아니라 인코딩 문제인 경우가 압도적** (B-4 참고) |
| 31 | `DEADLINE_HAS_EXPIRED_ERROR` | 활용기간 만료 → 마이페이지에서 연장신청 |
| 32 | `UNREGISTERED_IP_ERROR` | 신청한 IP와 호출 IP가 다름 |

### B-10. 일일 한도

- **기상청 단기예보 조회서비스 개발계정: 하루 10,000건** (상세 페이지에서 직접 확인된 값)
- 공공데이터포털 일반 안내의 "개발계정 1,000건"은 이 API에 해당하지 않는다. **10,000건**으로 쓸 것
- 운영계정은 활용사례 등록 시 증가 가능

## 단정하지 말 것 (조사에서 확인 안 된 것들)

1. 카카오 예전 메뉴명 `플랫폼 > Web > 사이트 도메인` 이 지금도 그대로 있는지 — **현재 문서 표기(`JavaScript SDK 도메인`)를 쓰고, "메뉴 이름이 바뀌었을 수 있으니 화면에서 'JavaScript SDK 도메인' 또는 '도메인'이라는 항목을 찾으세요"를 덧붙일 것**
2. 카카오 localhost 등록 방법의 공식 근거 — 개발자 사례 기준임을 밝힐 것
3. `autoload=false` — 이 책에서 아예 다루지 않는다
4. 개인 개발자에게 추가 심사·사업자 확인이 있는지 — 언급하지 말 것
5. 공공데이터포털 키가 실제로 동작하기까지의 정확한 시간 — "최대 한 시간쯤"으로 여유 있게
6. Encoding/Decoding 키 사용 규정 — 공식 규정이 아니라 관행임을 밝힐 것
7. 기상청 "발표시각 +10분" 표 — "10~15분쯤 지나서"로 여유 있게
