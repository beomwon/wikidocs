# 3.4 생성된 파일 투어 — 몰라도 되는 것과 알아야 하는 것

`invitation` 폴더를 열어보면 대략 이런 파일들이 있을 겁니다. (AI에 따라 조금씩 다를 수 있습니다.)

```
invitation/
├── main.py            ← 백엔드 (주방)
├── index.html         ← 프론트엔드 (홀)
├── requirements.txt   ← 부품 목록
└── (기타 폴더들)       ← 지금은 몰라도 됨
```

파일마다 "알아야 하는 수준"이 다릅니다. 정직하게 등급을 매겨 드립니다.

## main.py — ★★★ 역할은 알아야 함 (내용은 몰라도 됨)

우리 서비스의 **백엔드 본체**입니다. 열어보면 파이썬 코드가 있는데, 읽을 필요는 없습니다. 대신 이 파일의 세 가지 사실만 기억하세요.

1. `app = FastAPI()` 라는 줄이 어딘가에 있습니다. 이게 "여기가 백엔드 본부다"라는 선언이고, **5장에서 Vercel이 이 줄을 찾아서** 우리 서비스를 알아봅니다.
2. 축하 메시지를 받고, 저장하고, 돌려주는 로직이 전부 이 안에 있습니다.
3. 뭔가 기능을 바꾸고 싶으면 이 파일을 열 필요 없이 Claude에게 말하면 됩니다. Claude가 이 파일을 고칩니다.

## index.html — ★★ 역할만 알면 됨

친구 눈에 보이는 **초대장 화면 전부**입니다. 디자인이 마음에 안 들면 이 파일을 고치는 건데, 역시 직접 고칠 필요 없습니다. "제목을 더 크게"라고 말하면 Claude가 여기를 고칩니다.

## requirements.txt — ★★★ 배포 때 중요해짐

열어보면 몇 줄 안 됩니다.

```
fastapi
uvicorn
```

이건 **"이 프로젝트가 돌아가려면 이 부품들이 필요합니다"라는 목록**입니다. 지금은 내 컴퓨터에 부품을 설치했지만, 5장에서 Vercel 서버가 우리 코드를 받으면 **이 목록을 보고 부품을 알아서 설치**합니다. 이 파일이 없거나 부실하면 "내 컴퓨터에서는 되는데 서버에서는 안 되는" 사태의 주범이 됩니다.

## 몰라도 되는 것들 — ★

`__pycache__`, `.venv` 같은 폴더가 보일 수 있습니다. 파이썬이 자기 편하려고 만든 작업 폴더입니다. 지우지도 말고, 신경도 쓰지 마세요. (4장에서 "GitHub에 안 올리는 목록"에 넣는 것으로 처리 끝입니다.)

## 이 절의 핵심 그림

```
[친구 브라우저] ←── index.html (화면)
       ↕ API
[main.py (백엔드)] ── 실행에 필요한 부품 목록 = requirements.txt
```

> **🗣️ 폴더 구조가 책과 다르게 생성됐다면**
>
> ```
> 내 프로젝트 폴더 구조를 보여줄게. 각 파일이 무슨 역할인지
> 비개발자 눈높이로 한 줄씩 설명해줘. 그리고 백엔드 진입 파일이
> 뭔지 알려줘. [폴더 구조 붙여넣기]
> ```
>
> AI마다 폴더를 다르게 짜기도 합니다. 구조가 달라도 "백엔드 본체 / 화면 / 부품 목록" 세 가지만 짚을 수 있으면 이 책을 계속 따라올 수 있습니다.

다음 절에서는 지금 주소가 왜 `localhost:8000`인지 — 즉 지금 누가 서버 노릇을 하고 있는지 봅니다.
