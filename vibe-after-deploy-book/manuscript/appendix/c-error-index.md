# 부록 C. 에러 메시지별 대응 인덱스

## 쓰는 법

화면이나 로그에 뜬 문장에서 **영문 대문자가 길게 이어진 덩어리**나 **숫자 코드**를 하나 고르세요. `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`, `401`, `429`, `500` 같은 것들입니다. 그 조각을 이 페이지에서 찾으면(브라우저는 `Ctrl+F`, 폰은 페이지 내 검색) 무슨 뜻인지와 어느 절로 가야 하는지가 나옵니다.

에러 메시지가 아예 없고 화면만 이상하다면 바로 아래 「증상으로 찾기」부터 보세요.

그리고 대원칙 하나. **여기서 못 찾아도 괜찮습니다.** 이 인덱스는 자주 나오는 것을 모아둔 것이지 전부가 아닙니다. 원인을 모를 때 **에러 원문을 통째로 Claude에게 주는 것은 언제나 유효한 답**입니다(1권 3.6절). 요약하지 말고, 무섭게 생긴 영문도 지우지 말고 그대로 복사해 주세요. 해석은 여러분 몫이 아닙니다.

단 하나만 지키세요. **키와 비밀번호, 데이터베이스 접속 주소는 지우고 주세요.** 그 자리에 `(지움)`이라고 적어두면 됩니다. 이 부록 맨 아래에 그대로 복사해 쓸 수 있는 템플릿이 있습니다.

## 증상으로 찾기 (에러 메시지가 없을 때)

메시지는 없는데 화면만 이상한 경우입니다. 비개발자가 가장 많이 만나는 상황이기도 합니다.

| 증상 | 가장 흔한 원인 | 갈 곳 |
|---|---|---|
| 지도 자리가 회색 네모로만 보임 | 도메인 미등록 또는 불일치. 그다음이 키 종류 오류 | 4.6절, 3.6절 |
| 지도 자리가 아예 빈칸임 (회색조차 아님) | 지도를 담을 영역에 높이가 지정되지 않음. 키 문제가 아니라 화면 문제 | 4.6절 |
| 날씨 자리만 비어 있고 나머지는 정상 | 폴백이 동작한 것. 기상청 응답이 없어도 초대장은 열리도록 만들어 둔 결과 | 7.4절, 6.6절 |
| 초대장 전체가 안 열림 | 서버 쪽 실패. Vercel 런타임 로그에서 5로 시작하는 줄을 찾는다 | 11.2절, 7.2절 |
| 방명록을 써도 안 남음 | 데이터베이스 연결 실패. 관리자 페이지 2번 칸이 빨강인지 먼저 본다 | 9.3절, 9.7절 |
| `/admin`이 비밀번호를 안 물음 | 환경변수를 넣고 재배포를 안 했거나 잠금이 `/admin`에 안 걸림 | 10.5절, 10.2절 |
| `/admin`이 500 에러 | 열에 아홉은 환경변수 누락 | 9.7절, 3.5절 |
| 내 도메인만 안 되고 `vercel.app` 주소는 됨 | 도메인 문제로 확정. 지도라면 카카오 도메인 등록, 사이트 전체라면 DNS | 4.6절, 1권 9장 |
| 로컬에선 되는데 배포하면 안 됨 | Vercel 환경변수가 없거나 이름이 다르거나 재배포를 안 함 | 9.7절, 부록 B의 B-0 |
| 배포했는데 화면이 그대로임 | 브라우저가 옛 화면을 재활용 중. `Ctrl+Shift+R`로 강제 새로고침 | 부록 B의 B-0 |

## 카카오맵 관련

지도 문제는 원인이 일곱 가지인데 증상이 전부 똑같습니다. 그래서 **브라우저에서 `F12`를 눌러 `Console` 탭에 뜬 숫자를 보는 것**이 가장 빠른 지름길입니다. 아래 표의 왼쪽 열이 그 숫자입니다.

| 무엇을 봤나 | 뜻 | 할 일 | 갈 곳 |
|---|---|---|---|
| 콘솔에 `401 Unauthorized`, 지도는 회색 | 이 주소에서는 이 키를 쓸 수 없다는 뜻. 도메인 미등록이나 불일치가 가장 흔하다 | 카카오 개발자 사이트의 `JavaScript SDK 도메인` 목록에 지금 주소창에 보이는 도메인이 있는지 본다 | 4.6절, 3.4절 |
| `401`인데 도메인은 분명히 등록했다 | `http`와 `https`가 다르거나 포트가 빠졌다. 카카오에게는 서로 다른 주소다 | 실제 접속하는 형태 그대로 한 줄 더 등록한다. 로컬이면 `http://localhost:8000`처럼 포트까지 적는다 | 3.6절, 4.6절 |
| `401`인데 도메인도 프로토콜도 맞다 | `www.` 유무가 다르다 | `example.com`과 `www.example.com`을 둘 다 등록한다. 최대 10개까지 된다 | 3.4절 |
| `401`이고 키를 최근에 바꿨다 | JavaScript 키가 아니라 REST API 키를 넣었다. 초보자가 가장 많이 하는 실수다 | 카카오 콘솔의 `JavaScript 키` 값과 Vercel `KAKAO_JS_KEY` 값의 앞 네다섯 글자를 눈으로 맞춰 본다 | 3.3절, 3.6절 |
| 키도 도메인도 맞는데 계속 회색 | 카카오맵 사용 설정이 OFF다 | 앱의 `제품 설정` > `카카오맵`에서 `사용 설정`의 `상태`를 ON으로 켠다. 2026년 7월 21일부터는 심사나 신청 없이 스위치만 켜면 된다 | 4.6절, 3.6절 |
| 설정이 전부 멀쩡한데 회색 | 지도를 담을 영역에 높이가 없다. 키 문제가 아니라 화면 문제인데 증상이 똑같다 | Claude에게 "지도를 담는 영역에 높이가 지정되어 있는지 확인하고, 없으면 넣어줘"라고 시킨다 | 4.6절 |
| 콘솔에 `429 Too Many Requests` | 무료 할당량을 다 썼다는 뜻 | 하루 지나면 풀린다. 초대장 규모에서 이게 뜬다면 호출이 새고 있는 것이니 원인을 찾는다 | 2.4절, 4.6절 |
| `429`인데 오늘 처음 열어봤다 | 실습용 앱을 두 개 이상 만든 경우다. 무료 쿼터는 개발자 계정에서 **첫 번째로 활성화한 앱에만** 주어진다 | 두 번째 앱은 버리고 첫 앱으로 돌아가 설정을 고친다. 앱을 새로 만들어 해결하려 들지 않는다 | 3.2절, 3.6절 |
| 어제까지 되던 지도가 오늘 안 됨 | 할당량 소진이거나 카카오 쪽 일시 장애 | 카카오 콘솔에서 사용량을 확인하고, 이상이 없으면 기다린다 | 4.6절, 9.7절 |

원인을 반으로 줄이는 요령이 하나 있습니다. **Vercel이 준 `*.vercel.app` 주소로 접속해 보세요.** 거기서는 지도가 뜨는데 내 도메인에서만 회색이면 도메인 문제로 확정입니다. 둘 다 회색이면 키나 사용 설정 문제입니다. 이 한 번의 비교가 위 표의 절반을 지워 줍니다(4.6절).

## 기상청 날씨 API 관련

기상청 API는 에러 이름이 친절한 편입니다. 영어 대문자가 길게 이어져 무섭게 보이지만 **이름만 읽어도 원인이 거의 특정됩니다.** 에러는 `/api/weather`를 브라우저로 직접 열었을 때 화면에, 또는 터미널과 Vercel 런타임 로그에 나옵니다.

| 에러 이름 (코드) | 실제로 무슨 뜻인가 | 할 일 | 갈 곳 |
|---|---|---|---|
| `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` (30) | 등록되지 않은 키라는 뜻이지만 실제로는 인코딩 문제인 경우가 압도적이다 | 키를 다시 발급받지 말 것. Encoding 키와 Decoding 키를 서로 바꿔 넣어본다 | 5.4절 |
| `SERVICE_ACCESS_DENIED_ERROR` (20) | 발급받은 키가 기상청 서버에 아직 동기화되지 않았다 | 아무것도 고치지 말고 기다린다. 최대 한 시간쯤 걸릴 수 있다 | 5.6절 |
| `NO_OPENAPI_SERVICE_ERROR` (12) | 요청한 주소나 오퍼레이션 이름이 존재하지 않는다 | 오퍼레이션 철자를 본다. `getVillageFcst`가 아니라 `getVilageFcst`다 | 6.6절, 6.1절 |
| `APPLICATION_ERROR` (01) | `base_date` 또는 `base_time`이 잘못됐다. 아직 발표되지 않은 시각을 요청한 경우가 가장 흔하다 | 발표 시각 여덟 개 중 하나를 쓰고 있는지, 발표 직후 10~15분을 피했는지 확인한다 | 6.6절, 6.4절 |
| `NODATA_ERROR` (03) | 요청한 격자에 데이터가 없다 | `nx`, `ny` 오타이거나 국내 범위를 벗어난 값이다. 엑셀에서 값을 다시 확인한다 | 6.2절 |
| `INVALID_REQUEST_PARAMETER_ERROR` (10) | 파라미터 값의 형식이 이상하다 | `base_time`에 `0230`처럼 정시가 아닌 값이 들어갔는지, 날짜가 `YYYYMMDD` 형식인지 본다 | 6.6절 |
| `NO_MANDATORY_REQUEST_PARAMETERS_ERROR` (11) | 필수 파라미터가 빠졌다 | 파라미터 여덟 개가 다 들어갔는지 Claude에게 확인시킨다. `serviceKey`가 소문자 s인지도 함께 본다 | 6.1절, 6.6절 |
| `LIMITED_NUMBER_OF_SERVICE_REQUESTS_EXCEEDS_ERROR` (22) | 하루 요청 횟수를 넘겼다. 개발계정 기준 하루 10,000건이다 | 오늘은 기다린다. 그리고 캐싱을 반드시 붙인다 | 7.3절 |
| `DEADLINE_HAS_EXPIRED_ERROR` (31) | 활용기간이 만료됐다 | 공공데이터포털 마이페이지에서 연장신청을 한다 | 5.3절 |
| `TEMPORARILY_DISABLE_THE_SERVICEKEY_ERROR` (21) | 키가 일시 중지된 상태다 | 마이페이지 `활용신청 현황`에서 해당 API의 상태를 확인한다 | 5.3절 |
| `UNREGISTERED_IP_ERROR` (32) | 신청할 때 적은 IP와 실제로 호출한 IP가 다르다 | 마이페이지에서 신청 정보의 IP 설정을 확인한다 | 5.3절, 5.2절 |
| `DB_ERROR` (02) | 기상청 쪽 데이터베이스 오류다. 내 잘못이 아니다 | **기다리면 됩니다.** 고칠 것이 없다 | 7.4절 |
| `HTTP_ERROR` (04) | 제공기관 서버가 응답하지 않는다. 내 잘못이 아니다 | **기다리면 됩니다.** 고칠 것이 없다 | 7.4절 |
| `SERVICETIME_OUT` (05) | 일시적인 응답 지연이다. 내 잘못이 아니다 | **기다리면 됩니다.** 잠시 뒤 다시 해본다 | 7.4절 |

표 아래 세 줄을 특히 기억해 두세요. **내가 아무리 코드를 고쳐도 안 되는 종류의 에러가 존재합니다.** 이걸 모르면 멀쩡한 코드를 밤새 뜯어고치게 됩니다. 02, 04, 05가 뜨면 손을 떼는 것이 정답입니다.

그리고 30번에 대해 한 번 더 강조합니다. **`SERVICE_KEY_IS_NOT_REGISTERED_ERROR`를 봤을 때 절대로 키를 다시 발급받지 마세요.** 이름은 "등록되지 않은 키"라고 말하지만, 실제로는 키가 틀린 게 아니라 **Encoding 키와 Decoding 키를 잘못 골라 쓴 경우가 압도적**입니다. Encoding 키는 원본을 URL용으로 바꾼 것이라 코드에서 라이브러리가 한 번 더 인코딩하면 값이 망가집니다. 해결은 5.4절에 있고, 방법은 한 줄입니다. **지금 쓰는 것의 반대쪽 키로 바꿔 넣어보는 것.** 이것만으로 대부분 풀립니다. 키를 새로 발급받으면 20번(동기화 대기)이 추가로 붙어서 문제가 하나 더 늘어납니다.

## Vercel 로그에서 뭘 보나

[Vercel 대시보드](https://vercel.com/dashboard)에서 프로젝트를 열고 위쪽 `Logs` 탭을 누르세요. 화면이 다르면 `Logs` 또는 `Runtime Logs`라는 단어를 찾으면 됩니다.

볼 것은 두 가지뿐입니다. **상태 코드가 `5`로 시작하는 빨간 줄**(`500`, `502`, `504`)과 **그 줄의 시각**입니다. 5로 시작하면 서버가 요청을 처리하다 실패했다는 뜻이고, 이건 우리 쪽 문제입니다. 시각은 "문제가 났을 때"와 그 줄이 같은 시간대인지 맞춰 보기 위해 봅니다.

그다음 동작도 정해져 있습니다. **그 줄을 통째로 드래그해서 복사해 Claude에게 주는 것.** 영문을 해석할 필요는 없습니다. 자세한 읽는 법은 11.2절에 있습니다.

## 에러 원문을 AI에게 줄 때의 템플릿

여기까지 와도 안 풀렸다면 이 틀을 복사해서 빈칸을 채워 주세요. 1권 3.6절의 황금 템플릿을 이번 권 환경에 맞게 다듬은 것입니다.

> ```
> 1. 하려던 것:
> (예: 초대장에 모임 날 날씨 표시하기)
>
> 2. 어떤 프롬프트를 줬는지:
> (방금 Claude에게 준 지시를 그대로 붙여넣기)
>
> 3. 실제 결과:
> (화면에 뜬 것, 또는 아무것도 안 뜸)
>
> 4. 에러 메시지 전문:
> (브라우저 화면 / F12 콘솔 / 터미널 / Vercel 런타임 로그에서
>  복사한 전체. 요약하지 말고 그대로)
>
> 5. 환경:
> FastAPI + Vercel 서버리스 + Neon(PostgreSQL)
> + 카카오맵 JavaScript SDK + 기상청 단기예보 API
>
> 6. 어디까지 됐는지:
> (예: 초대장 본체와 방명록은 정상. 지도는 뜸. 날씨만 안 됨)
> ```

붙여넣기 전에 반드시 한 번 훑어보세요. **API 키, 비밀번호, `postgresql://`로 시작하는 데이터베이스 접속 주소는 지우고 주세요.** 지운 자리에는 `(지움)`이라고 적으면 됩니다. 그 값들이 없어도 원인 진단에는 아무 지장이 없습니다.

여섯 번 항목을 특히 빼먹지 마세요. **어디까지 됐는지**를 알려 주면 AI가 멀쩡한 부분을 건드리지 않습니다. 이 한 줄이 "안 되니까 처음부터 다시 만들어줘"로 잃게 될 것들을 지켜 줍니다.

같은 프롬프트를 세 번 넘게 시켰는데도 결과가 매번 다른 곳에서 어긋난다면, 붙들고 있지 말고 **부록 B**로 가세요. 손으로 확인하고 좁게 다시 시키는 방법이 순서대로 정리돼 있습니다.
