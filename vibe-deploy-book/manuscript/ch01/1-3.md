# 1.3 완성본 미리보기 — 내 도메인으로 보내는 나만의 초대장

이 책에서 우리는 **초대장 서비스**를 만듭니다. 왜 초대장이냐면, 초대장이야말로 원래부터 **"링크로 보내는 물건"**이기 때문입니다. 모바일 청첩장, 집들이 초대, 생일 파티 공지, 돌잔치 안내 — 전부 카톡 링크로 돌죠. 우리가 만드는 건 그 링크의 "내가 직접 만든 버전"입니다.

## 완성본은 이렇게 생겼습니다

주소창에는 여러분이 산 도메인이 떠 있습니다. 예를 들어:

```
https://invite.gildong.com
```

페이지를 열면:

- **초대장 본문** — 모임 이름, 날짜와 시간, 장소, 소개 문구. 배경과 분위기는 취향대로. (집들이면 아늑하게, 청첩장이면 우아하게 — AI에게 시키면 됩니다)
- **참석 여부(RSVP) 버튼** — "참석 / 불참" 을 누르면 기록됩니다.
- **축하 메시지 방명록** — 친구들이 이름과 메시지를 남기면 화면에 차곡차곡 쌓입니다.

겉보기엔 단순하지만, 이 안에 이 책의 모든 재료가 들어 있습니다.

## 이 단순한 페이지에 숨어 있는 것들

| 눈에 보이는 것 | 뒤에서 일하는 것 | 배우는 장 |
|---|---|---|
| 예쁜 초대장 화면 | 프론트엔드 (HTML) | 3장 |
| 메시지 남기기 버튼 | 백엔드 (FastAPI) | 3장 |
| 언제 접속해도 열림 | 서버 (Vercel) | 5장 |
| 메시지가 안 사라짐 | 데이터베이스 (Neon) | 7장 |
| `gildong.com` 주소 | 도메인 (호스팅케이알) | 8~9장 |
| 주소창의 자물쇠 | HTTPS (자동) | 9장 |

즉, 초대장 하나를 완성하면 웹 서비스가 돌아가는 **전체 그림을 한 바퀴 다 도는 것**입니다. 이게 이 책이 초대장을 고른 진짜 이유입니다.

## 왜 하필 "하나의 프로젝트"로 끝까지 가나요?

챕터마다 예제가 바뀌는 책은 따라 하다 길을 잃기 쉽습니다. 이 책은 초대장 하나를 3장에서 만들어서 12장까지 **같은 프로젝트를 계속 키워갑니다**. 중간에 문제가 터지고(6장에서 축하 메시지가 사라지는 사건이 일어납니다), 그 문제를 해결하면서 다음 개념이 필요해지는 구조입니다. 드라마 정주행하듯 따라오시면 됩니다.

그리고 마지막 10장에서 알게 됩니다 — 도메인을 하나 사면 `party.gildong.com`, `wedding.gildong.com`처럼 **초대장을 무한히 만들 수 있다**는 것을요. 이번에 만드는 건 첫 번째 초대장일 뿐입니다.
