# 2.3 열쇠를 어디에 두는가 — 브라우저에 둬도 되는 키, 절대 안 되는 키

키는 다 똑같이 숨겨야 한다고 배우면 3장에서 바로 혼란이 옵니다. 카카오맵 키는 브라우저에서 뻔히 보이거든요. 그건 사고가 아니라 원래 그런 겁니다. **키에는 브라우저에 내려가도 되는 것과 절대 내려가면 안 되는 것, 두 종류가 있습니다.**

## 카카오맵 JavaScript 키 — 숨길 수 없고, 숨기지 않습니다

지도는 정적인 그림이 아닙니다. 방문자가 손가락으로 끌면 따라 움직이고, 확대하면 새 조각을 더 불러옵니다. 이 일은 **방문자의 브라우저 안에서** 벌어집니다. 즉 카카오에 주문서를 보내는 주체가 내 서버가 아니라 방문자의 브라우저입니다. 그러니 키도 브라우저까지 같이 내려갈 수밖에 없습니다. 마음먹고 들여다보면 누구나 볼 수 있습니다.

그럼 어떻게 지키느냐. **키가 아니라 장소를 잠급니다.** 카카오 쪽 설정에 "이 키는 내 도메인에서 호출될 때만 유효하다"고 등록해 두는 방식입니다. 누가 내 키를 그대로 복사해 자기 사이트에 붙여도, 등록된 주소가 아니니 지도가 뜨지 않습니다.

이것이 3.4절의 **플랫폼 등록**이 선택이 아니라 필수인 이유입니다. 등록을 건너뛰면 내 사이트에서도 지도가 안 뜨고, 대충 등록하면 남이 내 키를 쓸 수 있습니다.

## 공공데이터포털 인증키 — 브라우저에 내려가면 안 됩니다

날씨는 사정이 다릅니다. 예보값은 한 번 받아 오면 되는 정보라, 방문자 브라우저가 기상청에 직접 물을 이유가 없습니다. 게다가 이 인증키에는 도메인 잠금 같은 장치를 기대하기 어렵습니다. 브라우저로 내려보내는 순간 그냥 공개된 키가 됩니다.

그래서 구조를 하나 끼웁니다. **내 서버가 대신 심부름을 다녀옵니다.**

1. 방문자 브라우저는 내 사이트의 창구 하나만 부릅니다. `/api/weather`입니다.
2. 내 서버가 인증키를 붙여 기상청에 물어봅니다. 이 통신은 방문자 눈에 보이지 않습니다.
3. 내 서버는 필요한 값만 골라 브라우저에 내려줍니다. 키는 서버 밖으로 나가지 않습니다.

방문자 입장에서는 우리 사이트에만 말을 걸었을 뿐이고, 기상청이라는 이름은 등장하지도 않습니다. 이 창구를 만드는 일은 6장에서 Claude에게 시킵니다.

## 두 방식 정리

| 구분 | 카카오맵 JavaScript 키 | 공공데이터포털 인증키 |
|---|---|---|
| 누가 부르나 | 방문자의 브라우저 | 내 서버 |
| 키가 어디에 있나 | 브라우저까지 내려간다 (숨길 수 없음) | 서버 안에만 있다 |
| 어떻게 지키나 | 카카오에 내 도메인을 등록해 다른 사이트에서 못 쓰게 막는다 | 애초에 밖으로 내보내지 않는다 |
| 환경변수 이름 | `KAKAO_JS_KEY` | `WEATHER_SERVICE_KEY` |
| 발급하는 장 | 3장 | 5장 |

> **자주 막히는 지점**
>
> *"카카오 키가 브라우저에서 보이는데, 이거 유출된 거 아닌가요?"* — 아닙니다. 그렇게 쓰라고 만든 키입니다. 대신 3.4절의 도메인 등록을 반드시 해 두세요. 그게 이 키의 자물쇠 전부입니다.
>
> *"그럼 지도도 서버가 대신 불러오면 더 안전하지 않나요?"* — 지도는 방문자가 끌고 확대할 때마다 계속 새 조각이 필요해서, 서버가 중간에 서면 느려지기만 하고 얻는 게 없습니다. 이건 원래 브라우저가 하는 일입니다.

다음 절은 돈 이야기입니다. 이 키들을 쓰다가 요금이 나올 일이 있는지 확인하고 갑니다.
