# 10.3 비밀번호는 환경변수로

코드는 준비됐지만 자물쇠에 아직 열쇠가 없습니다. 이제 실제 값을 넣습니다. 1권 4.4절에서 "비밀은 코드가 아니라 바깥에 둔다"는 원칙을 배웠고, 이 절은 그 원칙을 한 번 더 그대로 실행하는 절입니다. 새로 배울 것은 없고 손만 움직이면 됩니다.

## 좋은 비밀번호 만들기

먼저 비밀번호부터 정합니다. 지킬 것은 두 가지입니다.

- **다른 데서 쓰는 비밀번호를 재사용하지 마세요.** 메일이나 은행에서 쓰는 걸 여기에 또 쓰면, 이 사이트에서 새는 순간 그쪽까지 같이 뚫립니다. 관리자 페이지 전용으로 새로 만듭니다.
- **길게 만드세요.** 짧고 복잡한 것보다 긴 쪽이 훨씬 강합니다. 20자 이상을 권합니다. 어차피 외울 필요가 없습니다.

외울 필요가 없는 이유는 이 비밀번호를 브라우저나 비밀번호 관리자에 저장해 두고 쓸 것이기 때문입니다. 그러니 기억하기 좋게 만들려고 애쓰지 말고, 그냥 길고 무작위한 값으로 만드세요.

만들기 귀찮다면 **Claude에게 시켜도 됩니다.** "영문 대소문자와 숫자를 섞은 24자짜리 무작위 문자열을 하나 만들어줘"라고 하면 바로 줍니다. 단, 감각 하나만 기억하세요. **대화창에 남은 값을 그대로 쓰지 않는 게 좋습니다.** 대화 기록은 여기저기 남고, 나중에 그 대화를 캡처해서 어딘가에 올릴 수도 있습니다. 실제로 쓸 값은 새로 하나 더 받아서 대화 기록에 오래 남기지 않고 바로 옮기는 정도면 충분합니다.

## Vercel에 넣기

값이 준비됐으면 Vercel에 넣습니다. 3.5절과 5.5절에서 이미 두 번 해 본 절차와 똑같습니다.

1. [Vercel 대시보드](https://vercel.com/dashboard)에 로그인해서 이 프로젝트를 엽니다.
2. 위쪽 메뉴에서 `Settings`를 누릅니다.
3. 왼쪽 목록에서 `Environment Variables`를 누릅니다.
4. 이름(`Key` 또는 `Name`)에 `ADMIN_PASSWORD`를 정확히 입력합니다. 앞뒤에 빈칸이 들어가지 않게 주의하세요.
5. 값(`Value`)에 준비한 비밀번호를 붙여넣습니다.
6. 적용 범위를 고르는 칸이 있으면 `Production`을 포함해서 전부 선택합니다.
7. `Save`를 누릅니다.
8. `ADMIN_USER`도 같은 방법으로 하나 더 넣습니다. 값은 `admin`처럼 단순해도 됩니다. 자물쇠의 실제 역할은 비밀번호가 합니다.

화면이 이 설명과 다르게 보인다면 **`Environment` 또는 `환경변수`라는 단어**를 찾으세요. Vercel 화면 구성은 종종 바뀌지만 이 단어는 잘 바뀌지 않습니다.

## 값을 바꿨으면 다시 배포해야 합니다

여기서 가장 많이 걸리는 함정입니다. **환경변수를 저장했다고 바로 반영되지 않습니다.** 이미 배포되어 돌아가는 서버는 배포 시점의 값을 들고 있어서, 새 값을 쓰려면 배포를 한 번 더 해야 합니다.

Vercel의 `Deployments` 화면에서 가장 최근 배포의 점 세 개 메뉴를 열고 `Redeploy`를 누르면 됩니다. 또는 그냥 아무 커밋이나 하나 만들어 push해도 새로 배포됩니다. 이 규칙은 앞으로 `ADMIN_PASSWORD`를 바꿀 때마다 매번 적용됩니다. 10.4절에서 이 성질을 오히려 유용하게 써먹게 됩니다.

## 로컬 테스트용 .env

내 컴퓨터에서도 확인하려면 프로젝트 폴더의 `.env` 파일에 같은 이름으로 넣습니다.

```
ADMIN_USER=admin
ADMIN_PASSWORD=여기에_준비한_비밀번호
```

넣기 전에 **`.env`가 `.gitignore`에 들어 있는지 다시 확인하세요.** 1권 4.4절에서 만들어 뒀겠지만, 비밀이 하나 늘어난 지금 다시 확인할 값어치가 있습니다. 확신이 없으면 Claude에게 "`.env`가 git에 추적되고 있는지 확인해줘"라고 물으면 됩니다.

## 절대 하지 말 것

- **코드에 비밀번호를 직접 쓰기.** 그 순간 GitHub에 올라갑니다. Public 저장소면 몇 분 안에 수집됩니다.
- **비밀번호가 보이는 화면을 캡처해서 공유하기.** 질문하려고 올린 스크린샷 구석에 `.env` 파일이 열려 있는 사고가 흔합니다. 캡처 전에 화면을 한 번 훑어보세요.
- **AI 대화창에 실제 비밀번호를 붙여넣기.** 값은 사람이 직접 옮깁니다. AI에게는 "환경변수 이름은 `ADMIN_PASSWORD`야"까지만 말하면 충분합니다.
- **`.env` 파일을 GitHub에 올리기.** `.gitignore`가 막아주지만, 막아주는지 확인하는 것까지가 여러분의 몫입니다.

## 실수로 올려버렸다면

순서가 중요합니다. **비밀번호를 새 것으로 바꾸는 게 먼저입니다.** 지우는 것은 그다음입니다.

한 번 인터넷에 올라간 값은 이미 남이 봤다고 가정해야 합니다. GitHub에서 파일을 지워도 커밋 기록에는 남고, 그사이 누가 복사해 갔는지는 확인할 방법이 없습니다. 그러니 새 비밀번호를 만들어 Vercel에 넣고 재배포해서 옛날 값을 무효로 만든 다음, 기록 삭제를 처리하세요. 1권 4.4절에서 API 키에 대해 했던 이야기와 완전히 같은 원칙입니다.

기록을 지우는 방법은 Claude에게 물어보면 됩니다. 다만 **그 질문을 하는 창에도 실제 값은 적지 마세요.**
