# 4.3 내 코드 GitHub에 올리기

세이브(커밋)까지 했으니 이제 구름 위로 보냅니다(push). 순서는 둘: GitHub에 빈 저장소를 만들고 → 내 컴퓨터의 커밋을 그리로 push.

## 방법 1 — Claude에게 통째로 시키기 (권장)

> **Claude에게 이렇게 시키세요**
>
> ```
> 이 프로젝트를 내 GitHub 계정에 올리고 싶어.
> 1. GitHub에 "invitation"이라는 이름의 저장소를 만들고
> 2. 이 폴더의 코드를 거기에 push 해줘.
> 3. 처음이라 GitHub 인증이 안 되어 있을 수 있어. 인증이 필요하면
>    가장 쉬운 방법(gh 로그인 등)으로 단계별로 안내해줘.
> ```

Claude Code는 GitHub 명령 도구(gh CLI)를 쓸 수 있어서, 설치돼 있다면 저장소 생성부터 push까지 알아서 합니다. 처음 한 번은 **인증(로그인)** 절차가 낍니다 — "이 컴퓨터가 진짜 당신 것인지" GitHub이 확인하는 과정으로, 브라우저가 열리고 코드를 입력하는 식입니다. Claude의 안내를 따라가면 됩니다. 한 번 해두면 다시 할 일이 거의 없습니다.

## 방법 2 — 웹에서 저장소만 만들고 push는 시키기

Claude가 저장소 생성까지는 못 하는 환경이면:

1. github.com 로그인 → 우상단 **+** → **New repository**
2. 이름 `invitation`, **Private(비공개)** 선택 → **Create repository**
3. 생성 직후 화면에 나오는 안내 명령 블록(…or push an existing repository from the command line)을 통째로 복사해 Claude에게 "이거 실행해줘"

> **버튼 위치는 바뀔 수 있습니다.** 화면이 책과 다르면 화면을 캡처해서 Claude에게 "GitHub에서 새 저장소를 만들려는데 이 화면에서 뭘 눌러야 해?"라고 물어보세요.

## Public vs Private

- **Public(공개)** — 전 세계 누구나 코드를 볼 수 있음. 포트폴리오용.
- **Private(비공개)** — 나만 볼 수 있음. **초보 단계에서는 이걸 권합니다.** 실수로 비밀 정보를 올려도 피해가 제한되니까요. Vercel 배포는 Private이어도 아무 문제 없습니다.

## 확인: 올라갔나?

브라우저에서 `github.com/내아이디/invitation`을 열어보세요. `main.py`, `index.html`, `requirements.txt`가 보이면 성공입니다.

이제 여러분의 코드는 두 곳에 있습니다 — 내 컴퓨터, 그리고 GitHub. 이 순간부터 노트북이 강에 빠져도 코드는 무사합니다.

## 앞으로의 루틴

코드를 고칠 때마다 이 한 문장이면 됩니다.

> **수정할 때마다**
>
> ```
> 지금까지 수정한 내용을 "[디자인 수정]" 메시지로 커밋하고 push 해줘.
> ```

다음 장부터는 이 문장이 곧 **배포 명령**이 됩니다.

> **자주 막히는 지점**
>
> - *"Permission denied / 403 에러"* — 인증 문제입니다. 에러 전문을 Claude에게 주고 "GitHub 인증부터 다시 잡아줘"라고 하세요.
> - *"repository not found"* — 저장소 이름이나 주소가 어긋난 경우입니다. 역시 에러 전문 + "내 저장소 주소는 github.com/아이디/invitation이야"를 함께 주세요.
> - *"push했는데 GitHub 웹에서 안 보여요."* — 새로고침 먼저. 그래도 없으면 commit이 실제로 됐는지 Claude에게 "git 상태 확인해줘"라고 하세요.

그런데 잠깐 — push 하기 전에 반드시 알아야 할 것이 하나 있습니다. **올리면 안 되는 것들**입니다.
