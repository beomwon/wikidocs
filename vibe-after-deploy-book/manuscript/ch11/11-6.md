# 11.6 내보내기, QR, 그 밖의 아이디어 목록

여기서부터는 카탈로그입니다. 각 항목은 설명 몇 줄과 프롬프트 힌트 한 줄이 전부입니다. 필요한 것이 눈에 띄면 그 줄을 Claude에게 던지고, 아니면 넘기세요.

## 참석자 명단 CSV 내보내기

관리자 화면에서 참석자 목록을 눈으로 보는 것과, 그 목록을 엑셀에 붙여넣는 것은 다른 일입니다. 식당에 인원을 알려주거나, 좌석을 배치하거나, 답례품 개수를 세는 일은 결국 표에서 합니다. **CSV(씨에스브이)** — 엑셀에서 바로 열리는 표 형식 파일입니다.

이 책의 기능 중 실전에서 가장 확실하게 쓰이는 하나입니다.

> ```
> 관리자 페이지에 참석자 명단을 CSV 파일로 내려받는 버튼을 만들어줘.
> 한글이 엑셀에서 안 깨지게 처리해주고, 관리자만 받을 수 있게 해줘.
> ```

한글 깨짐 조건을 빼먹으면 엑셀에서 열었을 때 이름이 전부 외계어가 됩니다. 꼭 넣으세요.

## 초대장 링크 QR 코드

종이 청첩장이나 안내문에 인쇄할 때 필요합니다. 주소를 손으로 치게 하는 것보다 확실히 낫습니다. 한 번 만들어 이미지로 저장해두면 끝나는 일이라, 관리자 페이지에 붙이기보다 그냥 만들어 받는 편이 간단합니다.

> ```
> 우리 초대장 주소의 QR 코드 이미지를 만들어줘.
> 인쇄해도 깨지지 않게 큰 크기로, 배경은 흰색으로.
> ```

인쇄 전에 반드시 **본인 휴대폰으로 직접 찍어보세요.** 인쇄물은 다시 못 고칩니다.

## 방명록 인쇄용 한 장

모임이 끝난 뒤가 진짜입니다. 하객들이 남긴 축하 메시지를 한 장으로 모아 인쇄하거나 PDF로 저장해 두면, 그 자체가 선물이 됩니다. 결혼식이면 부모님께 드리기 좋고, 돌잔치면 아이가 나중에 볼 것이 됩니다.

이 기능을 만들려고 이 책을 샀다는 사람이 있어도 이상하지 않습니다.

> ```
> 방명록 전체를 인쇄하기 좋은 페이지로 만들어줘.
> 이름과 날짜, 메시지만 깔끔하게, 숨긴 글은 빼고,
> 브라우저 인쇄 기능으로 PDF 저장했을 때 글이 잘리지 않게 해줘.
> ```

## 여러 모임을 한 화면에서

초대장을 두 번째, 세 번째 만들게 되면 관리자 페이지도 여러 개가 됩니다. 1권 10장에서 서브도메인은 공짜라고 했으니 프로젝트는 계속 늘어날 겁니다. 그때 관리자 화면 하나에서 여러 사이트 상태를 함께 보고 싶어집니다.

각 사이트의 `/api/health` 주소를 목록으로 넘겨주고 한 화면에 나란히 그리게 하면 됩니다. 이미 만들어 둔 창구를 재활용하는 셈입니다.

> ```
> 관리자 페이지에 다른 사이트들의 상태도 함께 보여주는 칸을 만들어줘.
> 주소 목록은 환경변수로 넣을 테니 각각의 응답 여부만 색으로 표시해줘.
> ```

## 방문 추세 그래프

9.5절에서 만든 방문자 수는 오늘과 최근 7일 숫자입니다. 이걸 막대 몇 개로 그리면 흐름이 보입니다. 청첩장을 단체방에 뿌린 날 막대가 솟는 것을 보는 재미가 있습니다.

다만 이건 **재미의 영역**입니다. 운영에 필요해서가 아니라 보고 싶어서 만드는 것이고, 그렇다고 말하고 만드는 편이 정직합니다.

> ```
> 관리자 페이지 방문자 칸에 최근 14일 방문 수를 막대 그래프로 그려줘.
> 외부 그래프 라이브러리 없이 간단하게.
> ```

## 다크 모드

관리자 페이지를 새벽에 열 일이 있다면 눈이 편합니다. 초대장 본문까지 다크 모드로 만드는 것은 권하지 않습니다. 사진과 색이 어우러진 화면은 배경색이 뒤집히면 대개 망가집니다.

> ```
> 관리자 페이지만 어두운 배경으로 바꿔줘. 초대장 화면은 그대로 두고.
> ```

## 덧붙이지 말아야 할 것

목록을 여기까지 늘어놓고 정반대 말로 끝내겠습니다. **관리자 페이지에 기능을 계속 붙이면, 그 기능들 자체가 고장날 부품이 됩니다.**

8장에서 부품이 다섯 개일 때 원인을 좁히는 법을 배웠습니다. 부품이 열다섯 개가 되면 그 방법은 잘 안 통합니다. 게다가 새로 붙인 기능은 대개 급하게 붙인 것이라 제일 먼저 터집니다. 정작 모임 전날 밤에 터지는 것은 CSV 내보내기 같은 것이고, 그것 때문에 관리자 페이지 전체가 안 열리면 본전도 못 찾습니다.

**이 책이 만들어 준 여섯 칸이 안 흔들리는 것이, 기능 열 개를 더 가진 것보다 낫습니다.** 붙일 때마다 "이게 없어서 곤란했던 적이 실제로 있었나"를 한 번만 물어보세요. 없었다면 안 붙여도 됩니다.

마지막으로 경고 하나. **개인정보를 더 모으는 기능은 관리 책임도 함께 늘립니다.** 연락처를 받는 칸, 주소를 받는 칸을 추가하는 순간 여러분은 남의 개인정보를 보관하는 사람이 됩니다. 안 모으면 샐 일도 없습니다. 참석 여부와 이름만으로 충분한 모임에서는 딱 거기까지만 받으세요.

이 장은 여기까지입니다. 고를 것을 골랐다면, 다음 장에서 지금까지 만든 것 전체를 한 번 점검하고 마무리합니다.
