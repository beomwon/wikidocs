# 4.5 트러블슈팅 — push가 안 될 때

4장의 마무리로, GitHub 단계에서 겪는 대표 증상과 대처를 모았습니다. 공통 원칙은 3.6절 그대로입니다: **에러 원문을 통째로 Claude에게.**

## 증상별 처방전

| 증상 | 정체 | Claude에게 줄 말 |
|---|---|---|
| `Permission denied` / `403` | 인증 문제. 이 컴퓨터가 내 계정임을 증명 못 함 | "GitHub push에서 이 에러가 나. 인증 설정부터 다시 잡아줘" + 에러 전문 |
| `repository not found` | 저장소 주소가 틀렸거나 권한 없음 | "내 저장소는 github.com/아이디/invitation인데 이 에러가 나" + 에러 전문 |
| `rejected` / `non-fast-forward` | GitHub 쪽과 내 컴퓨터 쪽 기록이 어긋남 | "push가 rejected 됐어. 안전하게 해결해줘. 내 로컬 코드가 최신이야" + 에러 전문 |
| `Author identity unknown` | Git에 내 이름/이메일 등록 안 됨 | "git 사용자 이름과 이메일 설정해줘. 이름 OOO, 이메일 OOO" |
| 한글 파일명이 이상하게 보임 | 인코딩 표시 문제 (대부분 무해) | "git에서 한글 파일명이 깨져 보여. 설정 고쳐줘" |

## 만능 진단 프롬프트

뭐가 뭔지 모를 땐 이걸 쓰세요.

> **Claude에게**
>
> ```
> git 상태가 꼬인 것 같아. 다음을 순서대로 확인하고 진단해줘.
> 1. 지금 커밋 안 된 변경사항이 있는지
> 2. 원격 저장소(GitHub) 주소가 제대로 연결되어 있는지
> 3. 마지막 push가 언제였고 성공했는지
> 확인 결과를 알려주고, 문제가 있으면 안전한 순서로 해결해줘.
> "안전한"의 의미: 내 코드가 사라지는 명령은 실행 전에 나에게 먼저 알려줘.
> ```

마지막 줄이 포인트입니다. Git에는 코드를 날릴 수 있는 명령(`reset --hard`, `push --force` 등)이 있어서, AI에게도 **"위험한 건 실행 전에 알려달라"**는 가드레일을 걸어두는 습관이 좋습니다.

> **이 장에서 만든 것**
>
> - GitHub 계정 + `invitation` 비공개 저장소
> - 내 컴퓨터 ↔ GitHub 연결 (인증 완료)
> - add → commit → push 루틴 ("상자 담기 → 봉하기 → 발송")
> - `.gitignore` 안전장치 (비밀 정보 유출 원천 차단)
>
> 이로써 코드가 배포 컨베이어 벨트 위에 올라갔습니다.

다음 장, 드디어 첫 번째 "와"입니다. 5분 뒤 여러분의 초대장이 전 세계에서 열립니다.
