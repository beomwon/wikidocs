# 3.3 축하 메시지와 참석 여부 — 방명록(FastAPI)이 생기는 순간

초대장은 혼자 보는 게 아니죠. 친구들이 **뭔가를 남길 수 있어야** 초대장입니다. 축하 메시지와 참석 여부(RSVP)를 붙입니다.

> **Claude에게 이렇게 시키세요**
>
> ```
> 초대장에 두 가지 기능을 추가해줘.
>
> 1. 축하 메시지 방명록
> - 이름과 메시지를 입력하고 "남기기" 버튼을 누르면 저장되고,
>   페이지 아래에 최신순으로 쌓여서 보이게 해줘.
> - 이름이 비어 있거나 메시지가 200자를 넘으면 저장하지 말고
>   친절한 안내 문구를 보여줘.
>
> 2. 참석 여부(RSVP)
> - "참석" / "불참" 버튼을 만들고, 누르면 이름을 입력받아 저장해줘.
> - 현재까지 참석 몇 명, 불참 몇 명인지 숫자로 보여줘.
>
> 저장은 아직 메모리(파이썬 변수)에 해줘.
> 각 기능이 어떤 API 주소(GET/POST)로 동작하는지도 짧게 설명해줘.
> ```

## 방금 무슨 일이 일어났나

이 요청으로 여러분의 프로젝트에 처음으로 **진짜 백엔드 로직**이 생겼습니다. 2장의 식당 비유를 다시 쓰면:

- 친구가 메시지를 쓰고 버튼을 누름 → 홀(프론트)이 주방(백엔드)에 주문서를 보냄: **"이 메시지 저장해줘"** (POST 요청)
- 누군가 페이지를 열면 → 홀이 주방에 물어봄: **"지금까지 쌓인 메시지 다 줘"** (GET 요청)

Claude가 설명해 준 API 주소를 보면 아마 `/api/messages` 같은 게 있을 겁니다. 브라우저에서 재미있는 걸 하나 볼 수 있는데, 주소창에 이렇게 쳐보세요.

```
http://localhost:8000/docs
```

**FastAPI가 자동으로 만들어 준 API 설명서**가 뜹니다. 우리가 시킨 적도 없는데요. 여러분의 초대장에 어떤 주문 창구(API)들이 있는지 한눈에 보이고, 버튼을 눌러 직접 테스트도 됩니다. FastAPI가 개발자들에게 사랑받는 이유 중 하나를 방금 공짜로 얻었습니다.

## 검증이라는 개념

프롬프트에 "이름이 비어 있으면 저장하지 마"라는 조건을 넣었습니다. 이걸 **검증(validation)**이라고 합니다. 사용자가 뭘 입력할지는 아무도 모르기 때문에, 주방에서 이상한 주문서를 걸러내는 겁니다. FastAPI는 Pydantic이라는 도구로 이걸 처리하는데 — 이름까지 알 필요는 없습니다. "입력값 조건은 프롬프트에 미리 말해두면 AI가 걸러주는 코드를 짠다"만 기억하세요.

## 직접 테스트해 보세요

1. 이름과 메시지를 넣고 남겨보기 → 아래에 쌓이는지
2. 이름을 비우고 남겨보기 → 안내 문구가 뜨는지
3. 참석 버튼 → 숫자가 올라가는지
4. **새로고침** → 메시지가 그대로 있는지

4번까지 다 됩니다. 그런데 하나만 더 해보세요. **터미널에서 실행을 껐다가(Ctrl+C) 다시 켜 보세요.** ...메시지가 전부 사라졌죠?

이게 "메모리에 저장"의 정체입니다. 프로그램이 꺼지면 기억도 사라집니다. 지금은 "그렇구나" 하고 넘어가세요. 이 사건이 6장에서 훨씬 극적으로 다시 터지고, 7장에서 완전히 해결됩니다.

> **자주 막히는 지점**
>
> - *"버튼을 눌러도 아무 일도 안 일어나요."* — 브라우저에서 F12를 눌러 "콘솔(Console)" 탭을 여세요. 빨간 글씨가 있으면 그게 단서입니다. 복사해서 Claude에게 주며 "버튼을 눌러도 반응이 없고 콘솔에 이렇게 떠"라고 하세요.
> - *"수정했더니 아까 되던 게 안 돼요."* — 바이브코딩의 일상입니다. Claude에게 "방금 수정 이후 [뭐가] 안 돼. 원인을 찾아서 고쳐줘"라고 하면 됩니다. 4장에서 배울 Git이 이런 상황의 진짜 보험이 됩니다.

이제 동작하는 초대장이 생겼습니다. 다음 절에서는 Claude가 만들어 놓은 폴더 안을 구경하며 "뭐가 뭔지"를 잡습니다.
