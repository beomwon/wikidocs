# 10.3 이제 뭘 만들어도 올릴 곳이 있다

## 놀이터 확장 아이디어

서브도메인 놀이터에서 사람들이 실제로 많이 짓는 것들입니다. 전부 이 책에서 배운 구조(만들기 → push → Import → 서브도메인) 그대로 올라갑니다.

| 서브도메인 | 아이디어 | 난이도 |
|---|---|---|
| `me.` 또는 루트 | 자기소개 + 프로젝트 링크 모음 대문 | ★ (DB 불필요) |
| `wedding.` | 모바일 청첩장 (3.7절 레시피) | ★★ (이 책 그대로) |
| `baby.` | 돌잔치 초대장 + 성장 사진첩 | ★★ |
| `todo.` | 나만 쓰는 할 일 관리 | ★★ |
| `poll.` | 모임 날짜 투표 (언제 만날까?) | ★★ |
| `blog.` | 글 쓰는 공간 | ★★★ |

새 프로젝트를 시작할 때의 프롬프트 틀도 이제 정해져 있습니다.

> **🗣️ 새 프로젝트 시작 만능 틀**
>
> ```
> 새 프로젝트를 만들거야. [만들고 싶은 것 설명].
> 조건: FastAPI + main.py 구조, Vercel 서버리스 배포 전제,
> 데이터 저장이 필요하면 Neon(PostgreSQL) + DATABASE_URL 환경변수 방식.
> 새 폴더에 만들고, 완성되면 git 초기화와 GitHub 저장소 생성까지 해줘.
> ```
>
> 이 프롬프트 안의 단어들 — 서버리스, 환경변수, 저장소 — 전부 이 책에서 배운 것들입니다. 1장에서 약속했던 "질문할 수 있는 사람"이 된 겁니다.

## 관리 요령 두 가지

- **프로젝트가 늘면 목록을 적어두세요.** "어느 서브도메인 = 어느 저장소"를 메모장이든 대문 페이지든 한 곳에. 반년 뒤의 나는 반드시 잊습니다.
- **안 쓰는 프로젝트는 내려도 됩니다.** Vercel에서 프로젝트를 지우면 그 서브도메인만 죽고 나머지는 무사합니다. 도메인 놀이터의 좋은 점 — 철거도 부분 철거가 됩니다.
