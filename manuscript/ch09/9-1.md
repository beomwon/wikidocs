# 9.1 DNS 10분 이해 — 전화번호부 비유 하나로 끝내기

## 다시, 전화번호부

2.3절의 비유를 이제 실전 수준으로 키웁니다. **DNS는 인터넷의 전화번호부**입니다. 누가 `gildong.com`을 입력하면, 전화번호부에서 그 이름을 찾아 실제 주소(IP)를 알아내고, 거기로 접속합니다.

이 전화번호부에서 **내 도메인의 페이지를 편집할 권한**은 도메인 소유자인 여러분에게 있습니다. 도메인을 산 호스팅케이알 관리 화면의 "DNS 관리/설정" 메뉴가 바로 그 편집 화면입니다. 이 장에서 우리가 하는 일 전부는 결국 **그 페이지에 몇 줄 적는 것**입니다.

## 레코드: 전화번호부의 한 줄

전화번호부에 적는 한 줄 한 줄을 **레코드(record)**라고 합니다. 종류가 여럿인데, 우리에게 필요한 건 딱 셋입니다.

**① A 레코드 — "이 이름은 이 IP야" (직통 번호)**

```
gildong.com  →  76.76.21.21
```

이름을 IP 주소(숫자)에 직접 연결합니다. Vercel이 "이 IP로 연결하세요"라고 알려주면 그 숫자를 적는 식입니다.

**② CNAME 레코드 — "이 이름은 저 이름한테 물어봐" (착신 전환)**

```
invite.gildong.com  →  어쩌구.vercel-dns.com
```

이름을 IP가 아니라 **다른 이름**에 연결합니다. "invite.gildong.com의 주소요? 어쩌구.vercel-dns.com이랑 같은 곳이에요"라는 뜻입니다. Vercel처럼 서버 IP가 수시로 바뀔 수 있는 서비스는 이 방식을 좋아합니다 — 자기네 이름 쪽에서 IP를 알아서 갱신하면 되니까요.

**③ NS(네임서버) 레코드 — "이 도메인의 전화번호부는 저 회사가 관리해" (관리 위임)**

한 줄이 아니라 **페이지 전체를 누가 관리할지** 정하는 레코드입니다. 기본값은 도메인을 산 곳(호스팅케이알)이 관리하는 것인데, 이걸 통째로 Vercel에 위임할 수도 있습니다. 이게 다음다음 절에서 배울 "방법 B"입니다.

## 딱 하나만 더: 루트 도메인 vs 서브도메인

- `gildong.com` — 도메인 그 자체. **루트(root)** 또는 apex라고 부릅니다.
- `invite.gildong.com`, `www.gildong.com` — 앞에 뭐가 붙은 것. **서브도메인**입니다.

기술적인 사정으로 **루트에는 보통 A 레코드를, 서브도메인에는 CNAME을** 씁니다. 왜 그런지는 몰라도 됩니다. "Vercel 대시보드가 알려주는 대로 적는다"가 우리의 행동 원칙이고, Vercel은 상황에 맞는 레코드를 정확히 알려줍니다.

## 이 장 전체의 요약 (미리)

```
방법 A: 전화번호부는 호스팅케이알에 두고, 몇 줄만 적는다 (A/CNAME 레코드 추가)
방법 B: 전화번호부 관리를 통째로 Vercel에 맡긴다 (NS 변경)
```

둘 다 결과는 같습니다: `gildong.com` → Vercel → 내 초대장. 이제 실제로 해봅시다.

> **미리 답해드리는 질문**
>
> *"TTL이라는 항목도 있던데요?"* — 레코드마다 붙는 **유효기간**입니다. "이 정보를 몇 초 동안 믿고 써도 되는지"의 값인데, 기본값 그대로 두면 됩니다. 9.5절(전파)에서 이 개념이 왜 존재하는지 자연스럽게 이해됩니다.
