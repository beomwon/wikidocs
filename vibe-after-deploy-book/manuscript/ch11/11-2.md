# 11.2 최근 활동 타임라인과 에러 모아보기

"어제 새벽에 사이트가 잠깐 안 됐던 것 같다"는 말을 들었을 때 필요한 기능입니다. 지금의 관리자 화면으로는 확인할 방법이 없습니다.

## 지금 화면의 한계 — 현재만 보인다

여섯 칸은 전부 **지금 이 순간**을 말합니다. 열어보니 전부 초록입니다. 그런데 그건 지금 초록이라는 뜻이지, 계속 초록이었다는 뜻이 아닙니다. 새벽 3시에 한 번 죽었다가 4시에 살아났다면 아침에 열어본 화면은 아무 일도 없었다는 얼굴을 하고 있습니다.

그래서 칸을 하나 더 만듭니다. 현재를 보여주는 칸이 아니라 **시간순으로 쌓이는 칸**입니다.

## 무엇을 적고, 무엇을 안 적을 것인가

여기서 판단이 필요합니다. 기록은 많을수록 좋은 게 아닙니다. 정상 동작을 전부 적으면 정작 중요한 한 줄이 그 안에 묻힙니다.

적을 것:

- 방명록이 달린 순간, 참석 응답이 들어온 순간 (드물게 일어나고, 궁금한 일)
- 날씨 호출 실패 (외부 탓이지만 내 화면이 영향받는 일)
- DB 응답이 유난히 느렸던 순간
- 배포가 일어난 시각 (사고의 원인 절반은 "방금 뭘 바꿨다"입니다)

안 적을 것:

- 정상적인 페이지 방문 하나하나
- 성공한 날씨 호출, 성공한 DB 조회
- 30초마다 도는 관리자 화면 자동 갱신

기준은 하나입니다. **나중에 다시 볼 만한 일인가.** 아니면 안 적습니다.

## Vercel 로그 읽는 법 — 볼 것은 딱 두 가지

타임라인을 만들기 전에, 이미 존재하는 기록을 보는 법을 알아두면 좋습니다. Vercel은 우리가 아무것도 안 해도 요청 기록을 남기고 있습니다.

[Vercel 대시보드](https://vercel.com/dashboard)에서 우리 프로젝트를 열고, 위쪽 탭에서 `Logs`를 누르세요. 화면 구성이 이 설명과 다르면 `Logs` 또는 `Runtime Logs`라는 단어를 찾으면 됩니다.

들어가면 시각, 요청 경로, 상태 코드가 줄줄이 나옵니다. 낯선 숫자와 영문이 가득해서 압도당하기 쉬운데, **비개발자가 여기서 볼 것은 딱 두 가지입니다.**

1. **빨간 줄** — 정확히는 상태 코드가 `5`로 시작하는 줄입니다. `500`, `502`, `504` 같은 것들이고, 이건 "서버가 요청을 처리하다 실패했다"는 뜻입니다. 우리 쪽 문제입니다.
2. **그 줄의 시각** — 언제 일어났는지. 하객이 "몇 시쯤 안 됐다"고 한 시각과 맞춰보기 위해서입니다.

나머지는 전부 무시해도 됩니다. `404`(그런 주소 없음)는 대개 남이 아무 주소나 두드려본 것이고, `200`은 잘 된 겁니다.

그리고 빨간 줄을 찾았다면 다음 동작도 정해져 있습니다. **그 줄을 통째로 드래그해서 복사해 Claude에게 주는 것.** 1권 3.6절에서 배운 그대로입니다. 여러분이 그 영문을 해석할 필요는 없습니다. 좋은 재료를 옮기는 것까지가 여러분 몫입니다.

## 타임라인 칸 만들기

> **Claude에게 이렇게 시키세요**
>
> ```
> 관리자 페이지에 "최근 활동" 카드를 하나 추가해줘.
>
> [조건]
> - 시간순으로 최근 것이 위에 오게 목록으로 보여줘.
> - 기록할 것: 방명록 등록, 참석 응답, 날씨 API 실패,
>   DB 응답 지연, 배포 감지.
> - 정상적인 페이지 방문이나 성공한 조회는 기록하지 마.
> - 에러로 분류되는 항목은 목록에서 눈에 띄게 표시해줘.
> - 기록이 무한히 쌓이지 않게 최근 200건만 남기고
>   오래된 것은 자동으로 지워지게 해줘.
> - 기록을 남기다 실패해도 초대장 동작에는 영향이 없게 해줘.
> ```

**마지막 두 줄이 핵심입니다.** 기록은 두는 순간부터 자라고, 자라는 것은 언젠가 DB 용량을 먹습니다. 처음부터 상한을 정해두면 그 걱정을 안 해도 됩니다. 그리고 기록 기능은 어디까지나 보조 장치라서, 그것 때문에 초대장이 안 열리는 일은 절대 없어야 합니다.

**성공 판정** — 관리자 페이지를 열어둔 채 다른 창에서 초대장에 방명록을 하나 남겨보세요. 30초 안에 최근 활동 칸 맨 위에 그 줄이 나타나면 성공입니다.

> **자주 막히는 지점**
>
> - *"타임라인이 계속 비어 있어요."* — 기록을 남기는 코드가 실제 동작 지점에 안 붙은 경우입니다. "방명록 저장이 끝나는 자리에서 활동 기록을 남기고 있는지 확인해줘"라고 시키세요.
> - *"에러가 같은 내용으로 수십 줄 쌓여요."* — 한 번 터진 에러가 반복 호출되는 중입니다. "같은 내용이 연달아 오면 한 줄로 묶고 횟수만 표시해줘"를 추가하세요.
