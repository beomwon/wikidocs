# 부록 B. AI가 제대로 못 만들었을 때 — 수동 세팅 가이드

## 이 부록을 여는 순간

본문 어딘가에서 "안 되면 부록 B로 오세요"라는 문장을 보고 오셨을 겁니다. 대개 이런 상황입니다.

- 프롬프트를 그대로 붙여넣었는데 화면에 아무 변화가 없다
- 만들어지긴 했는데 사양과 다르다 (카드가 여섯 칸이어야 하는데 네 칸이라든가)
- 어제까지 되던 것이 오늘 안 된다
- 같은 프롬프트를 세 번 넘게 시켰는데 매번 다른 곳이 빠진다

먼저 드릴 말씀은 **하지 말아야 할 것**입니다.

**통째로 다시 시키지 마세요.** "안 되니까 처음부터 다시 만들어줘"는 가장 손해가 큰 선택입니다. AI는 그 말을 들으면 잘 돌아가던 부분까지 새로 씁니다. 카드 한 칸이 모자라서 다시 시켰는데 잠금이 풀리고, 폴백이 사라지고, 멀쩡하던 방명록이 깨지는 식입니다. 고칠 곳은 하나였는데 고칠 곳이 다섯 개가 됩니다.

대신 할 일은 **어디까지 됐고 어디부터 안 되는지를 가르는 것**입니다. 이 부록은 그 가르는 작업을 도와주는 도구 세 가지로 되어 있습니다.

1. **눈으로 확인하기** — 어떤 화면을 열어 어떤 단어가 있는지 보는 것. 코드를 읽는 게 아닙니다.
2. **더 좁은 프롬프트로 다시 시키기** — 전체가 아니라 한 조각만 콕 집어 시키는 것. 이 부록에 있는 프롬프트는 전부 이 형태입니다.
3. **정말 손으로 넣어야 하는 최소한의 것** — 환경변수 값, 좌표 숫자 정도입니다. 그 이상은 없습니다.

여러분은 여전히 파이썬을 몰라도 됩니다. 이 부록에서 코드를 직접 짜라고 하는 곳은 한 군데도 없습니다.

**어디부터 볼지 모르겠다면 이 부록 맨 아래 「공통 진단표」부터 보세요.** 증상만 알면 어느 항목으로 갈지 그 표가 알려줍니다. 그리고 어느 항목으로 가든, 먼저 B-0을 지나가야 합니다.

## B-0. 먼저 확인할 다섯 가지 (전 항목 공통)

지도든 날씨든 관리자 페이지든, 안 될 때 공통으로 보는 다섯 가지입니다. 경험상 절반 이상이 여기서 끝납니다. AI를 다시 부르기 전에 이 표부터 훑으세요.

| 확인할 것 | 확인하는 방법 |
|---|---|
| 1. 환경변수 이름 철자 | Vercel의 `Environment Variables` 목록을 열어 이 책의 네 이름과 글자 하나까지 같은지 본다 |
| 2. 넣거나 바꾼 뒤 재배포 | Vercel의 `Deployments`에서 가장 최근 배포 시각이 환경변수를 만진 시각보다 나중인지 본다 |
| 3. 값 앞뒤의 공백과 따옴표 | 값을 편집 화면에서 다시 열어 커서를 맨 끝으로 옮겨 본다. 빈칸이 있으면 커서가 글자 뒤에서 한 칸 더 간다 |
| 4. 로컬 `.env`와 `.gitignore` | 프로젝트 폴더의 `.env` 파일을 열어 같은 이름이 있는지 보고, `.gitignore` 파일에 `.env` 한 줄이 있는지 본다 |
| 5. 지금 보는 화면이 최신 배포인가 | 브라우저에서 `Ctrl+Shift+R`(맥은 `Command+Shift+R`)로 강제 새로고침한 뒤 다시 본다 |

이 책에서 쓰는 환경변수 이름은 아래 네 개에 1권의 `DATABASE_URL`을 더한 다섯 개가 전부입니다. 대문자와 밑줄까지 그대로여야 합니다.

```
KAKAO_JS_KEY
WEATHER_SERVICE_KEY
ADMIN_USER
ADMIN_PASSWORD
DATABASE_URL
```

몇 가지 덧붙입니다.

- **2번이 가장 흔합니다.** 환경변수는 저장만으로는 반영되지 않습니다. 값을 바꿨으면 반드시 다시 배포해야 합니다. 3.5절과 5.5절에서 이미 말했지만, 실제로 가장 많이 잊는 항목입니다.
- **3번의 따옴표.** 키를 복사할 때 앞뒤 큰따옴표까지 딸려 들어가는 일이 있습니다. Vercel 환경변수 값에는 따옴표를 붙이지 않습니다. 값만 넣습니다.
- **4번의 `.gitignore`.** `.env`가 여기 없으면 키가 GitHub에 올라갔을 수 있습니다. 그 경우는 B-4로 가세요. 급한 일입니다.
- **5번.** 배포는 끝났는데 브라우저가 예전 화면을 보여주고 있는 경우가 있습니다. 판정은 항상 강제 새로고침 뒤에, 가능하면 시크릿 창에서 하세요.

## B-1. 카카오맵이 안 뜰 때 손으로 확인하기

지도 자리가 회색이거나 아예 비어 있을 때입니다. 아래 순서대로 확인하세요. 위쪽 항목일수록 흔한 원인입니다.

**1. 카카오맵 사용 설정이 켜져 있는가**

카카오 개발자 사이트에서 내 앱을 열고 `제품 설정` > `카카오맵` > `사용 설정`의 `상태`가 **ON**인지 봅니다. OFF면 키가 아무리 맞아도 지도가 안 뜹니다. 2026년 7월 21일부터는 이 스위치만 켜면 되고, 예전처럼 신청하고 심사를 기다릴 필요가 없습니다. 화면 구성이 설명과 다르면 `카카오맵`이라는 단어를 찾으세요.

**2. 지금 접속 중인 주소가 도메인 목록에 있는가**

`앱 설정` > `앱` > `플랫폼 키` > `JavaScript 키` 아래의 **`JavaScript SDK 도메인`** 을 엽니다. 메뉴 이름이 바뀌었을 수 있으니 화면에서 `JavaScript SDK 도메인` 또는 `도메인`이라는 항목을 찾으면 됩니다.

여기서 대충 보면 안 됩니다. **지금 브라우저 주소창에 있는 주소와 글자 단위로 비교하세요.**

| 자주 어긋나는 곳 | 예 |
|---|---|
| 프로토콜 | 접속은 `https`인데 `http`만 등록돼 있음 |
| `www.` 유무 | 등록은 `https://example.com`인데 접속은 `https://www.example.com` |
| Vercel 주소 | 내 도메인만 등록하고 `.vercel.app` 주소는 빠뜨림 |
| 로컬 포트 | `http://localhost`만 등록하고 `:8000` 포트를 빠뜨림 |

도메인은 최대 10개까지 등록할 수 있으니 내 도메인, `www.` 붙은 형태, `.vercel.app` 주소, 로컬 주소를 다 넣어 두세요. 로컬 주소에 포트를 붙이는 방법은 공식 안내에 나와 있지는 않지만 실제로는 이렇게 하면 동작합니다.

**3. 코드에 SDK 스크립트 태그가 실제로 들어갔는가**

이건 코드를 안 열고도 확인할 수 있습니다.

1. 초대장 페이지를 브라우저에서 엽니다.
2. 페이지 빈 곳에서 마우스 오른쪽 버튼을 눌러 `페이지 소스 보기`를 선택합니다. (단축키는 `Ctrl+U`)
3. 글자가 잔뜩 나오면 `Ctrl+F`로 검색창을 열고 **`dapi.kakao.com`** 을 찾습니다.

**한 건도 안 나오면 SDK가 아예 안 붙은 것입니다.** 아래 프롬프트 중 두 번째를 쓰세요.

**4. `appkey=` 뒤에 값이 들어 있는가**

3번에서 찾은 줄을 그대로 보세요. 정상이면 이런 모양입니다.

```
<script type="text/javascript" src="//dapi.kakao.com/v2/maps/sdk.js?appkey=발급받은_JavaScript_키"></script>
```

장소 검색이나 주소 변환을 함께 쓴다면 뒤에 `&libraries=services`가 더 붙어 있을 수 있습니다. 둘 다 정상입니다.

문제는 `appkey=` 뒤가 **비어 있거나**, `undefined`, `None`, `{{...}}` 같은 글자가 있는 경우입니다. 그건 키가 틀린 게 아니라 **환경변수가 화면까지 전달되지 않은 것**입니다. B-0의 1번과 2번을 다시 보고, 아래 두 번째 프롬프트를 쓰세요.

**5. REST API 키를 넣지 않았는가**

가장 많이 하는 실수입니다. 카카오는 앱 키를 네 개 줍니다. 지도에 쓰는 것은 **JavaScript 키** 하나뿐입니다. REST API 키를 넣으면 지도가 안 뜹니다. 카카오 개발자 사이트의 앱 키 화면에서 `JavaScript 키` 항목의 값을 다시 복사해 `KAKAO_JS_KEY`에 넣고 재배포하세요.

**6. 지도를 담을 영역에 높이가 있는가**

키도 도메인도 다 맞는데 회색인 마지막 경우입니다. 지도가 들어갈 자리에 높이가 정해져 있지 않으면 지도는 높이 0으로 그려집니다. 화면에는 아무것도 없거나 회색 띠만 보입니다. 증상이 키 문제와 똑같아서 오래 헤매게 되는 항목입니다. 아래 첫 번째 프롬프트로 해결합니다.

### 한 조각만 다시 시키는 프롬프트

## B-2. 날씨가 안 나올 때 손으로 확인하기

날씨는 우리 서버가 기상청에 대신 물어보는 구조입니다. 그래서 **중간 지점을 직접 열어보는 것**으로 원인을 반으로 가를 수 있습니다.

브라우저 주소창에 이렇게 칩니다.

```
내주소/api/weather
```

여기서 무엇이 나오느냐로 갈립니다.

| 화면에 보이는 것 | 원인 | 할 일 |
|---|---|---|
| `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` | 키가 틀린 게 아니라 인코딩 문제인 경우가 압도적 | Encoding 키와 Decoding 키를 서로 바꿔 넣고 재배포 (5.4절) |
| `SERVICE_ACCESS_DENIED_ERROR` | 발급한 키가 기상청 쪽에 아직 동기화되지 않음 | 기다린다. 최대 한 시간쯤 뒤에 다시 (5.6절) |
| `NO_OPENAPI_SERVICE_ERROR` | 오퍼레이션명 오타 | `getVilageFcst` 철자 확인. `getVillageFcst`가 아니다 |
| `NODATA_ERROR` | 격자 좌표가 틀렸거나 국내 범위 밖 | `nx`, `ny` 값을 엑셀에서 다시 찾는다 (6.2절) |
| `APPLICATION_ERROR` | `base_date` 또는 `base_time`이 잘못됨 | 아직 발표되지 않은 시각을 요청했을 가능성 (6.1절) |
| `INVALID_REQUEST_PARAMETER_ERROR` | 파라미터 값이 이상함 | `base_time`에 `0230`처럼 정시가 아닌 값을 넣지 않았는지 |
| `LIMITED_NUMBER_OF_SERVICE_REQUESTS_EXCEEDS_ERROR` | 하루 요청 한도 초과 | 개발계정 기준 하루 10,000건. 다음 날 다시 |
| `DEADLINE_HAS_EXPIRED_ERROR` | 활용기간 만료 | 공공데이터포털 마이페이지에서 연장신청 |
| 아무것도 안 나오거나 500 에러 | 우리 서버 코드 쪽 문제 | Vercel 런타임 로그를 그대로 Claude에게 (B-6) |
| 날씨 값이 정상으로 나옴 | 서버는 정상. 화면에 그리는 쪽 문제 | 아래 세 번째 프롬프트 |

마지막 줄이 중요합니다. `/api/weather`는 멀쩡한데 초대장에 날씨가 안 보인다면, 키도 API도 다 정상이고 **화면 쪽만 고치면 되는 상태**입니다. 범위가 확 줄어듭니다.

### 손으로 한 번 직접 불러보기

`/api/weather`가 이상하면, 기상청에 **내가 직접** 물어봐서 키가 살아 있는지만 따로 확인할 수 있습니다. 이게 되면 "키는 멀쩡하고 코드 문제"라는 판정이 섭니다. 반대로 이것도 안 되면 키나 신청 쪽 문제입니다.

주소창에 아래 모양으로 만들어 넣습니다. 괄호로 표시한 자리에 내 값을 넣으세요.

```
(요청주소)?serviceKey=(Encoding키)&pageNo=1&numOfRows=100&dataType=JSON&base_date=(YYYYMMDD)&base_time=(HHMM)&nx=(격자X)&ny=(격자Y)
```

- **(요청주소)** — 5.2절에서 받은 활용가이드 문서에 적혀 있습니다. 더 빠른 방법은 Claude에게 "우리 코드가 기상청에 보내는 요청 주소를 그대로 알려줘"라고 물어보는 것입니다.
- **(Encoding키)** — 주소창에 직접 붙여 넣을 때는 반드시 **Encoding 키**입니다. Decoding 키를 넣으면 특수문자 때문에 실패합니다. 반대로 코드 안에서는 Decoding 키가 맞는 경우가 많습니다(5.4절). 공식 규정이 아니라 관행이니, 한쪽으로 안 되면 다른 쪽으로 바꿔 보세요.
- **(YYYYMMDD)** — 오늘 날짜입니다. `base_date`는 최근 3일까지만 조회됩니다.
- **(HHMM)** — `0200`, `0500`, `0800`, `1100`, `1400`, `1700`, `2000`, `2300` 중 **지금 시각보다 이미 지난 것**을 고릅니다. 발표 직후에는 아직 데이터가 없으니 10~15분쯤 지난 뒤에 부르세요.
- **(격자X), (격자Y)** — 6.2절에서 찾아둔 `nx`, `ny` 값입니다.

한 가지 함정이 더 있습니다. 포털 문서에는 `ServiceKey`(대문자 S)로 적혀 있지만, 실제 호출은 **`serviceKey`(소문자 s)** 로 하는 것이 통용됩니다. 이 대소문자 하나 때문에 실패하는 경우가 실제로 있습니다. 코드 쪽도 마찬가지라, 계속 키가 등록되지 않았다는 에러가 나면 Claude에게 "파라미터 이름을 소문자 `serviceKey`로 보내고 있는지 확인해줘"라고 물어보세요.

> ```

## B-3. 관리자 페이지가 사양대로 안 나왔을 때

9장에서 만든 관리자 페이지의 확정 사양은 이렇습니다. 이것과 다르면 어긋난 것입니다.

- 주소는 `/admin`, 상태 창구는 `/api/health`
- 카드는 **여섯 칸** (서버 / 데이터베이스 / 카카오맵 / 날씨 / 방문자 / 방명록·참석)
- 상태는 **초록·노랑·빨강 세 가지 색**, 그리고 색 옆에 글자
- **30초마다 자동 갱신**
- 5번, 6번 카드는 색 없이 숫자와 목록만

### 흔한 어긋남과 대응

| 어긋난 모습 | 위험도 | 대응 |
|---|---|---|
| 카드가 모자라거나 시키지 않은 카드가 생김 | 낮음 | 모자란 칸만 지목해 다시 시킨다 |
| 색 없이 숫자만 나옴 | 낮음 | 판정 기준을 숫자로 못 박아 다시 시킨다 |
| 자동 갱신이 없어 손으로 새로고침해야 함 | 낮음 | 갱신 부분만 다시 시킨다 |
| 시키지 않은 로그인 화면이 붙어 있음 | 중간 | 지우게 한다. 잠금은 10장 방식으로 |
| 시키지 않은 삭제 버튼이 붙어 있음 | **높음** | **즉시 지운다** |
| `/api/health`가 비밀 정보를 뱉고 있음 | **높음** | 아래 확인 후 즉시 수정 |

**삭제 버튼이 왜 위험한가.** 9장 단계의 `/admin`은 아직 잠기지 않은 상태입니다. 주소를 아는 누구나 열 수 있는 화면에 삭제 버튼이 있다는 뜻입니다. 방명록이 통째로 사라질 수 있습니다. 발견 즉시 지우게 하고, 10장에서 잠근 뒤에 11.1절에서 다시 붙이세요.

### 한 칸씩 고치는 프롬프트 틀

이 항목의 핵심은 아래 틀입니다. 괄호 안만 바꿔 쓰세요. **전체를 다시 만들지 말라는 첫 줄과, 건드리지 말 것을 지정하는 마지막 줄을 빼지 마세요.** 그 두 줄이 이 틀의 전부입니다.

### `/api/health`가 비밀 정보를 뱉고 있는지 확인하기

`/api/health`는 일부러 잠그지 않는 창구입니다(10.2절). 열어두는 만큼 내용이 안전해야 합니다. 시크릿 창에서 `내주소/api/health`를 열고 아래 네 가지가 눈에 띄는지만 보세요. 글자를 다 읽을 필요는 없습니다.

- 비밀번호나 API 키처럼 보이는 긴 문자열
- `postgresql://`로 시작하는 데이터베이스 접속 주소
- 에러 메시지 원문이나 코드 파일 경로
- 방명록 내용이나 방문자 개인정보

하나라도 있으면 10.5절의 프롬프트로 즉시 고치세요. 그리고 **실제로 키나 비밀번호가 밖으로 나가고 있었다면, 고치는 것보다 그 값을 새것으로 바꾸는 게 먼저입니다.** 그 방법은 다음 항목에 있습니다.

## B-4. 잠금이 안 걸렸을 때

이 책에서 가장 위험한 실패입니다. 다른 항목은 안 되면 불편할 뿐이지만, 이건 이미 새어 나갔을 수 있습니다.

### 확인 1. 시크릿 창에서 `/admin`이 비밀번호를 묻는가

평소 쓰던 브라우저 창은 판정에 쓸 수 없습니다. 이미 통과한 상태이기 때문입니다. 시크릿 창(`Ctrl+Shift+N` 또는 `Ctrl+Shift+P`)에서 `내주소/admin`을 엽니다.

- 회색 비밀번호 창이 뜬다 → 정상
- 관리자 화면이 그냥 보인다 → **잠금이 안 걸렸습니다**

같은 창에서 `내주소`(초대장 본체)도 열어 보세요. 여기서 비밀번호를 물으면 사이트 전체가 잠긴 것이고, 하객이 초대장을 못 봅니다. 이것도 즉시 고쳐야 합니다.

### 확인 2. 코드에 비밀번호가 그대로 박혀 있지 않은가

AI는 친절하려는 습성이 있어서, 환경변수가 없을 때를 대비해 코드에 임시 비밀번호를 슬쩍 적어두는 일이 자주 있습니다. 그 코드는 GitHub에 올라갑니다.

찾는 방법은 두 가지입니다.

**(a) Claude에게 시킨다.** 비개발자에게 가장 현실적인 방법입니다.

> **Claude에게 이렇게 시키세요**
>
> ```
> 이 프로젝트 전체에서 비밀번호, API 키, 접속 주소가 코드에
> 직접 적혀 있는 곳을 전부 찾아줘.
> 파일 이름과 몇 번째 줄인지 목록으로 알려줘.
> 기본값으로 슬쩍 적어둔 것도 포함해서 찾아줘.
> 찾기만 하고 아직 고치지는 마.
> ```

목록이 나왔으면 그다음에 이렇게 시킵니다.

> **Claude에게 이렇게 시키세요**
>
> ```
> 방금 찾은 곳들을 전부 환경변수에서 읽도록 고쳐줘.
> 기본값도 넣지 마. 값은 내가 Vercel과 .env 에 직접 넣을게.
> ADMIN_PASSWORD 가 비어 있으면 서버가 시작할 때 에러가 나게 해줘.
> 잠금이 풀린 채로 조용히 실행되면 안 돼.
> ```

**(b) 직접 검색한다.** 코드 편집기에서 프로젝트 폴더를 연 뒤, 전체 검색 기능으로 **실제 비밀번호 문자열 자체**를 넣고 찾아봅니다. 한 건이라도 나오면 그 파일에 비밀번호가 박혀 있는 것입니다. `.env` 파일에서 나오는 건 정상입니다.

### 확인 3. GitHub에 `.env`가 올라가 있지 않은가

브라우저에서 내 GitHub 저장소를 엽니다. 파일 목록에 **`.env`가 보이면 안 됩니다.** 보인다면 그 안의 값은 이미 인터넷에 공개된 것으로 간주하세요. 저장소가 Private이어도 마찬가지로 취급하는 편이 안전합니다.

`.env`가 안 보여도 방심하지 마세요. 확인 2에서 코드에 박힌 값이 나왔다면, 그 값도 이미 올라간 것입니다.

### 이미 올라갔다면 — 순서가 중요합니다

**지우는 것보다 바꾸는 것이 먼저입니다.** 파일을 지워도 GitHub에는 예전 기록이 남습니다. 지웠으니 됐다고 넘어가면 안 됩니다. 새 값으로 갈아치워야 예전 값이 무의미해집니다.

급한 순서대로 씁니다.

**1. `ADMIN_PASSWORD` — 지금 바로 바꿉니다.** 셋 중 가장 급하고, 가장 쉽습니다. 새 비밀번호를 정해 Vercel의 `Environment Variables`에서 값을 바꾸고 재배포하면 끝입니다. 로컬 `.env`도 같이 바꾸세요.

**2. `WEATHER_SERVICE_KEY` — 서버에서만 쓰는 키라 노출되면 안 되는 값입니다.** 공공데이터포털에서 `마이페이지` > `데이터활용` > `Open API` > `활용신청 현황` > 해당 API를 엽니다. 인증키가 있는 그 화면(5.3절)에서 키를 다시 발급받는 항목이 있는지 확인하세요. 화면에 그런 항목이 안 보이면 포털 고객센터에 문의하는 것이 정확합니다. 남이 내 키를 쓰면 하루 10,000건 한도가 내 것이 아니라 남의 호출로 소진됩니다.

**3. `KAKAO_JS_KEY` — 조금 다릅니다.** 이 키는 원래 브라우저에 노출되는 키입니다(2.3절). 페이지 소스만 봐도 보이는 값이라, 노출 자체가 사고는 아닙니다. **이 키의 진짜 방어막은 도메인 등록입니다.** `JavaScript SDK 도메인`에 내 주소만 들어 있는지, 모르는 주소가 끼어 있지 않은지 확인하세요. 그래도 키를 바꾸고 싶다면 카카오 개발자 사이트의 앱 키 화면에서 키를 다시 발급받는 항목을 찾습니다. 다만 **앱을 새로 만들어 해결하려 들지는 마세요.** 무료 쿼터는 개발자 계정에서 첫 번째로 활성화한 앱에만 제공되므로, 두 번째 앱은 유료 설정 없이는 지도가 아예 안 됩니다.

**4. 그다음에 `.env`를 저장소에서 내리고 `.gitignore`에 넣습니다.** 이건 Claude에게 시키면 됩니다.

> **Claude에게 이렇게 시키세요**
>
> ```
> .env 파일이 GitHub 저장소에 올라가 있어.
> .gitignore 에 .env 를 추가하고, 저장소에서 .env 를 빼줘.
> 내 컴퓨터의 .env 파일은 지우지 마.
> 안에 있던 값은 이미 새로 발급받아 교체했어.
> ```

## B-5. 타임아웃·캐싱·폴백이 안 들어갔을 때

7장의 조건이 세 개나 되다 보니, AI가 한두 개를 빠뜨리는 일이 흔합니다. 타임아웃은 붙었는데 폴백이 없는 식입니다.

문제는 이게 **평소에는 안 보인다는 것**입니다. 잘 될 때는 셋 다 있는 것처럼 보입니다. 그래서 일부러 고장 내서 확인합니다. 7.5절의 성공 판정과 같은 방법입니다.

### 확인 방법

1. Vercel 대시보드에서 `Settings` > `Environment Variables`로 갑니다.
2. **`WEATHER_SERVICE_KEY`의 원래 값을 어딘가에 복사해 둡니다.** 이 단계를 건너뛰면 되돌릴 수 없습니다.
3. 값 끝에 글자 몇 개를 덧붙여 **일부러 틀린 키**로 만들고 저장합니다.
4. `Deployments`에서 다시 배포합니다. 환경변수는 재배포해야 반영됩니다.
5. 배포가 끝나면 초대장 주소를 새 탭에서 엽니다.

판정 기준은 세 가지입니다.

| 확인할 것 | 정상 | 이상 |
|---|---|---|
| 초대장이 열리는가 | 정상적으로 열림 | 흰 화면 또는 에러 화면 |
| 날짜, 장소, 방명록 | 전부 그대로 보임 | 일부가 사라지거나 깨짐 |
| 날씨 자리 | 폴백 문구로 조용히 바뀜 | 빨간 경고 박스 또는 자리 자체가 사라짐 |

**확인이 끝났으면 반드시 원래 값으로 되돌리고 다시 배포하세요.** 이걸 잊고 넘어가면 모임 당일까지 날씨가 안 나옵니다. 실제로 가장 흔한 사고입니다.

캐싱은 눈으로 확인하기 어렵습니다. 서버리스에서는 백엔드가 자주 새로 깨어나 캐시가 비어 있는 것처럼 보이는 게 정상입니다(7.3절). 짧은 시간에 초대장을 여러 번 열었을 때 Vercel 런타임 로그의 기상청 호출 횟수가 연 횟수보다 적으면 동작하는 것입니다.

### 한 조각씩 다시 시키는 프롬프트

빠진 것만 골라 하나씩 시키세요. 세 개를 한 번에 다시 시키면 또 하나가 빠집니다.

> **Claude에게 이렇게 시키세요**
>
> ```
> 다른 건 건드리지 말고 타임아웃만 확인해줘.
> 기상청 호출에 4초 타임아웃이 걸려 있는지 보고,
> 없으면 넣어줘. 4초 안에 응답이 없으면 기다리지 말고 포기해.
> 캐싱과 폴백 코드는 지금 있는 그대로 둬.
> ```

> **Claude에게 이렇게 시키세요**
>
> ```
> 다른 건 건드리지 말고 캐싱만 확인해줘.
> 기상청 응답을 15분 동안 캐시해서 재사용하고 있는지 보고,
> 없으면 넣어줘. 방문자가 몰려도 15분에 한 번만 물어보게 해줘.
> 이 프로젝트는 Vercel 서버리스라 함수가 요청이 올 때만
> 잠깐 실행되고 사라져. 그 전제로 짜줘.
> 타임아웃과 폴백 코드는 그대로 둬.
> ```

> **Claude에게 이렇게 시키세요**
>
> ```
> 다른 건 건드리지 말고 폴백만 확인해줘.
> 지금은 WEATHER_SERVICE_KEY 를 일부러 틀리게 하면
> 초대장 페이지 전체가 에러가 나.
> 날씨 호출이 실패해도 날짜, 장소, 방명록은 반드시 정상적으로
> 나와야 해. 날씨 자리만 조용히 바뀌게 해줘.
> 마지막으로 성공한 값이 있으면 "○시 기준"을 붙여 보여주고,
> 없으면 "날씨 정보를 불러오지 못했습니다"를 표시해줘.
> 경고색은 쓰지 마.
> 지도 쪽 폴백과 다른 코드는 건드리지 마.
> ```

폴백을 고쳤다면 위의 확인 방법으로 한 번 더 검증하세요. 고쳤다는 말만 믿고 넘어가지 않는 것이 이 절의 요령입니다.

## B-6. 그래도 안 될 때 — AI에게 제대로 물어보는 법

여기까지 왔다면 남은 방법은 하나입니다. **재료를 제대로 갖춰서 다시 묻는 것.** 1권 3.6절의 황금 템플릿을 이 책 상황에 맞게 다시 드립니다.

> **에러 전달 황금 템플릿 (2권용)**
>
> ```
> 문제가 생겼어. 상황을 정리해서 줄게.
>
> 1. 하려던 것:
>    (예: 관리자 페이지에 비밀번호 잠금을 붙이려고 했어)
> 2. 내가 준 프롬프트:
>    (앞에서 붙여넣었던 프롬프트를 그대로)
> 3. 기대한 결과:
>    (예: 시크릿 창에서 /admin 을 열면 비밀번호 창이 뜨는 것)
> 4. 실제 결과:
>    (예: 비밀번호 창 없이 그냥 열림)
> 5. 에러 메시지 전문:
>    (터미널, F12 콘솔, Vercel 런타임 로그에서 복사한 것 전체)
> 6. 환경:
>    FastAPI + Vercel 서버리스 + Neon(PostgreSQL).
>    GitHub 에 push 하면 자동 배포되는 구조야.
> 7. 어디까지 됐나:
>    (예: 카드 여섯 칸은 정상. 잠금만 안 걸림)
>
> 원인을 설명해주고, 어느 파일의 어디를 고쳐야 하는지 알려줘.
> 관련 없는 부분은 건드리지 마.
> ```

- **2번과 7번이 1권 템플릿에 없던 항목입니다.** 이 책은 프롬프트로 굴러가므로, 무엇을 시켰는지가 가장 중요한 단서입니다. 그리고 "어디까지 됐나"를 적으면 AI가 멀쩡한 부분을 헤집지 않습니다.
- **5번은 요약하지 말고 통째로.** 에러 메시지는 여러분이 읽으라고 나오는 게 아니라 AI에게 전달하라고 나오는 것입니다.
- **글자 복사가 어려우면 화면을 캡처해서 붙여넣어도 됩니다.** Vercel이나 카카오 개발자 사이트처럼 처음 보는 관리 화면에서 특히 유용합니다.

### 절대 함께 주지 말아야 할 것

**실제 API 키 값, 실제 비밀번호, 데이터베이스 접속 주소(`postgresql://`로 시작하는 것)는 붙여넣지 마세요.** 로그나 응답 안에 섞여 있다면 그 부분만 지우고 주면 됩니다. 값을 몰라도 AI는 원인을 찾습니다. 필요한 건 "환경변수 이름"이지 "환경변수 값"이 아닙니다.

캡처 화면도 마찬가지입니다. Vercel 환경변수 화면을 캡처할 때 값이 그대로 보이는 상태라면 그 부분을 가리고 주세요.

### 마지막 수단 — 되돌리기

같은 문제로 다섯 번 이상 주고받고 있고, 오히려 처음보다 더 망가졌다면 되돌릴 때입니다. 1권 4장에서 배운 커밋이 여기서 쓰입니다. 잘 되던 시점이 기록으로 남아 있으니, 거기로 돌아가면 됩니다.

> **Claude에게 이렇게 시키세요**
>
> ```
> 지금 작업을 되돌리고 싶어.
> 최근 커밋 목록을 보여주고, 마지막으로 정상 동작하던 시점으로
> 돌아가는 방법을 순서대로 알려줘.
> 되돌리기 전에 지금 상태를 따로 보관해두는 방법도 같이 알려줘.
> 나는 git 을 잘 모르니까 명령어를 한 줄씩 설명과 함께 줘.
> ```

Vercel의 `Deployments` 목록에도 예전 배포가 남아 있습니다. 잘 되던 배포를 찾아 다시 배포하는 방법도 있으니, 위 프롬프트에 "Vercel에서 예전 배포로 돌아가는 방법도 알려줘"를 덧붙여도 됩니다.

되돌린 뒤에는 **한 번에 하나씩** 다시 붙이세요. 지도만, 다음에 날씨만, 다음에 관리자 화면만. 한꺼번에 시켜서 망가진 것을 되돌렸는데 다시 한꺼번에 시키면 같은 자리에서 또 넘어집니다.

## 공통 진단표 — 어디부터 안 되는가

증상만 알면 어디로 갈지 이 표가 알려줍니다. 이 부록의 목차라고 생각하세요. 어느 항목으로 가든 **B-0을 먼저 지나가는 것**을 잊지 마세요.
