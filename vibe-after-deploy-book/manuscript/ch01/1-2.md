# 1.2 이 책에서 붙일 세 가지 — 지도, 날씨, 관리자 화면

이번 권에서 초대장에 붙일 것은 세 가지입니다. 순서에 이유가 있습니다.

## 하나. 지도 — "오시는 길"이 없으면 결국 또 보내게 됩니다

지금 초대장에는 장소가 글자로만 적혀 있습니다. "서울 마포구 OO아파트 101동." 이걸 받은 친구는 주소를 길게 눌러 복사한 뒤, 지도 앱을 따로 열어서 붙여넣습니다. 몇 명은 그냥 카톡으로 물어봅니다. "거기 어디로 가면 돼?"

초대장 안에 지도가 있으면 이 왕복이 사라집니다. 우리는 **카카오맵**을 씁니다. 국내 주소와 건물 이름을 가장 잘 알아보고, 개인이 쓰는 규모에서는 무료이며, 무엇보다 지도를 누르면 카카오맵 앱으로 이어져 길찾기까지 바로 넘어갑니다. 3장에서 열쇠를 받고, 4장에서 붙입니다.

## 둘. 날씨 — 야외 모임이라면 제일 궁금한 것

모임이 마당이든 공원이든 캠핑장이든, 참석자가 초대장을 다시 열어보는 이유는 대개 하나입니다. 그날 비 오나?

날씨는 **공공데이터포털**에서 제공하는 기상청 단기예보를 씁니다. 국가가 무료로 여는 데이터라 카드 등록이 없고, 우리나라 예보라는 점에서 가장 믿을 만합니다. 5장에서 열쇠를 받고, 6장에서 붙입니다.

## 셋. 관리자 화면 — 앞의 둘을 붙이는 순간 필요해집니다

여기가 이 책의 논리입니다.

지금 초대장에서 고장날 수 있는 곳은 사실상 두 군데였습니다. 내 사이트(Vercel)와 데이터베이스(Neon). 그런데 지도와 날씨를 붙이는 순간, 고장날 수 있는 곳이 이렇게 늘어납니다.

| 붙이기 전 | 붙인 후 |
|---|---|
| 내 서버 | 내 서버 |
| 데이터베이스 | 데이터베이스 |
| | 카카오맵 |
| | 기상청 |

늘어난 두 곳의 공통점은 **내 것이 아니라는 점**입니다. 카카오 서버가 잠깐 느려지거나, 기상청 쪽에서 응답이 안 오거나, 발급받은 열쇠가 만료되면 내 초대장 화면이 이상해집니다. 나는 아무것도 안 했는데요.

그러면 친구에게 "안 열려요" 카톡이 왔을 때 확인해야 할 것이 네 가지가 됩니다. 이걸 매번 하나씩 뜯어보는 건 불가능합니다. **네 개의 상태를 한 화면에 모아 놓는 것** — 그게 관리자 페이지입니다. 8장에서 설계하고, 9장에서 만들고, 10장에서 비밀번호로 잠급니다.

그래서 이 책의 순서는 지도 → 날씨 → 관리자 화면입니다. 관리자 화면을 먼저 만들면 보여줄 게 없거든요. 지킬 것이 생긴 다음에 지키는 도구를 만듭니다.
