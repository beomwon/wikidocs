# 4.4 절대 올리면 안 되는 것 — 비밀번호, API 키, .gitignore

이 절은 이 책에서 몇 안 되는 **"이건 진짜 조심하세요"** 절입니다. 가볍게 읽지 마세요.

## 사고는 이렇게 납니다

7장에서 우리는 데이터베이스 접속 주소라는 걸 갖게 됩니다. 생김새는 이렇습니다.

```
postgresql://myuser:비밀번호@어딘가.neon.tech/dbname
```

이 한 줄에는 **비밀번호가 들어 있습니다.** 이런 게 코드 파일에 적힌 채로 GitHub에 push되면 — 특히 Public 저장소라면 — 몇 분 안에 자동 수집 봇들이 긁어갑니다. 남의 DB에 접속해 데이터를 지우거나, 유료 API 키라면 수백만 원어치를 몰래 쓰는 일이 실제로 일어납니다. 뉴스에 나오는 "개발자 실수로 클라우드 요금 폭탄" 사건의 상당수가 이겁니다.

**비밀 정보의 종류**: 비밀번호, 데이터베이스 접속 주소, **API 키**(외부 서비스를 쓸 수 있는 열쇠 문자열), 토큰. 공통점은 "이 문자열만 있으면 나인 척할 수 있다"는 것.

## 해법 1: 비밀은 .env 파일에 격리한다

개발자들의 표준 관행: 비밀 정보는 코드에 쓰지 않고 **`.env`라는 별도 파일**에 모아 둡니다.

```
DATABASE_URL=postgresql://myuser:비밀번호@어딘가.neon.tech/dbname
```

코드는 "DATABASE_URL이라는 이름의 값을 가져와서 써"라고만 되어 있고, 실제 값은 `.env`에만 존재합니다. (이 구조는 7장에서 실제로 쓰면서 다시 배웁니다.)

## 해법 2: .gitignore로 택배 상자에서 원천 배제한다

**`.gitignore`**는 "Git아, 이 목록의 파일은 **절대 상자에 담지 마**"라는 명단 파일입니다. 여기에 `.env`를 적어두면, `git add`를 해도 `.env`는 담기지 않습니다. 실수 자체가 불가능해지는 거죠.

> **🗣️ Claude에게 이렇게 시키세요 (지금 바로)**
>
> ```
> 이 프로젝트에 파이썬 프로젝트 표준 .gitignore 파일을 만들어줘.
> .env, __pycache__, .venv 등이 반드시 포함되게 해줘.
> 그리고 혹시 지금 프로젝트 안에 비밀번호나 API 키 같은 민감 정보가
> 코드에 하드코딩되어 있는지 검사해서 알려줘.
> ```

아직 우리 프로젝트엔 비밀이 없지만, **비밀이 생기기 전에 울타리부터** 치는 겁니다. 7장에서 DB 접속 주소가 생겼을 때 이 울타리가 여러분을 지킵니다.

## 이미 올려버렸다면

> ```
> 실수로 비밀번호가 든 파일을 GitHub에 push했어.
> 1) 그 비밀번호/키를 어디서 새로 발급받아 교체해야 하는지
> 2) GitHub에 올라간 기록을 지우는 방법
> 순서대로 알려줘.
> ```
>
> 중요한 순서: **키 교체가 먼저, 기록 삭제는 그다음**입니다. 한 번 인터넷에 올라간 비밀은 "이미 유출됐다"고 간주하고 무효화하는 게 원칙입니다. 지우는 것만으로는 안전해지지 않습니다.

> **🚧 자주 막히는 지점**
>
> *".gitignore에 넣었는데도 계속 올라가요."* — 이미 한 번 커밋된 파일은 .gitignore에 뒤늦게 넣어도 계속 추적됩니다. Claude에게 ".env가 이미 git에 추적되고 있는데 추적을 중단시켜줘"라고 하세요.
