# 8.3 한 화면에 모을 것 — 대시보드 설계도

8.2절의 다섯 단계를 화면 하나로 옮기면 이렇게 됩니다. 주소는 `/admin`, 화면은 카드 여섯 칸입니다. 이 여섯 칸이 이 책 끝까지 바뀌지 않는 우리 대시보드의 확정 사양입니다.

![](https://static.wikidocs.net/images/page/386115/ch08-dashboard.png)

## 여섯 칸

| 칸 | 보여주는 것 | 판정 기준 |
|---|---|---|
| 1. 서버 | `/api/health` 응답 여부와 응답 시간 | 응답 있으면 초록, 1초 초과 노랑, 무응답 빨강 |
| 2. 데이터베이스 | Neon 연결 성공 여부, 확인 쿼리 소요 시간 | 성공 초록, 1초 초과 노랑, 실패 빨강 |
| 3. 카카오맵 | 관리자 화면에 실제로 띄운 작은 지도가 그려지는지 | 그려지면 초록, 안 그려지면 빨강 |
| 4. 날씨 | 기상청 API 응답 상태, 마지막 성공 시각 | 정상 초록, 캐시로 버티는 중 노랑, 실패 빨강 |
| 5. 방문자 | 오늘 방문 수, 최근 7일 방문 수 | 색 없음 (숫자만) |
| 6. 방명록·참석 | 방명록 총 개수와 최근 5건, 참석/불참/미정 집계 | 색 없음 (숫자와 목록) |

**헬스체크(health check)** — 서버가 살아 있는지 묻는 아주 짧은 질문입니다. `/api/health` 주소로 물으면 서버가 "살아 있습니다" 한 마디만 돌려줍니다. 9장에서 만듭니다.

## 어느 칸이 어느 단계를 대신하나

| 8.2절 단계 | 대신하는 칸 |
|---|---|
| 1. 나도 안 되나 | 5번 방문자 — 오늘 방문 수가 평소처럼 오르고 있으면 다른 사람들은 잘 보고 있다는 뜻입니다 |
| 2. 주소가 문제인가 | 카드가 아니라 **관리자 페이지 자체** — `내도메인/admin`이 안 열리는데 `*.vercel.app/admin`은 열리면 DNS 문제입니다 |
| 3. 사이트는 열리나 | 1번 서버 (껍데기) + 3번 카카오맵 + 4번 날씨 (부분) |
| 4. 저장이 되나 | 2번 데이터베이스 + 6번 방명록 최근 5건의 시각 |
| 5. 로그 | 넣지 않습니다 (아래 참고) |

2단계가 카드가 아니라는 점이 재미있습니다. 관리자 페이지가 내 도메인으로 열렸다는 사실 자체가 이미 DNS가 정상이라는 증거이기 때문입니다. 화면이 뜬 순간 2단계는 통과입니다.

## 설계 원칙 세 가지

### 1. 숫자보다 색

응답 시간이 340밀리초인지 820밀리초인지는 우리에게 의미가 없습니다. 우리가 알고 싶은 건 오직 하나, **괜찮은가 아닌가**입니다. 그래서 각 칸은 초록·노랑·빨강 세 가지 색으로 결론부터 말합니다. 초록이면 넘어가고, 빨강이면 멈춰서 봅니다. 숫자는 색 아래 작게 곁들이는 참고 자료일 뿐입니다.

세 가지로 제한하는 것도 일부러입니다. 색이 다섯 가지가 되면 그때부터 색깔의 뜻을 외워야 하고, 외워야 하는 순간 3초 안에 못 읽습니다.

### 2. 폰에서 보인다

문제는 항상 밖에 있을 때 생깁니다. 결혼식장 대기실에서, 지하철에서, 카페에서 연락을 받습니다. 노트북을 펴야만 볼 수 있는 대시보드는 정작 필요한 순간에 못 봅니다.

그래서 카드는 가로로 늘어놓지 않고 **세로로 쌓습니다.** 폰 화면 폭에 한 칸씩 채워 넣고 아래로 스크롤하는 구조입니다. 그리고 급한 순서대로 위에서부터 놓습니다. 서버와 데이터베이스가 1, 2번인 이유가 이겁니다. 이 둘이 초록이면 최악은 아니라는 뜻이라, 화면을 켜자마자 맨 위 두 칸만 봐도 절반은 판정이 끝납니다.

### 3. 누르지 않아도 갱신된다

문제가 있을 때는 화면을 켜 두고 지켜보게 됩니다. 그때 새로고침 버튼을 계속 누르게 만들면 안 됩니다. 화면은 **30초마다 스스로 갱신됩니다.** 켜 두기만 하면 상태가 바뀌는 순간 색이 따라 바뀝니다.

30초라는 간격에도 이유가 있습니다. 더 짧게 잡으면 우리 서버가 자기 자신에게 계속 질문을 던지게 되고, 카카오와 기상청에도 쓸데없이 자주 묻게 됩니다. 2장에서 본 무료 할당량이 관리자 페이지 때문에 닳으면 곤란하니까요.

## 안 넣을 것

무엇을 넣을지만큼 중요한 것이 무엇을 빼느냐입니다. 아래 세 가지는 일부러 넣지 않습니다.

- **방문자의 개인정보** — 누가 어떤 IP로 언제 들어왔는지 같은 것은 우리에게 필요 없습니다. 필요도 없는 개인정보를 모아 두면 관리할 책임만 생깁니다. 방문자는 숫자로만 셉니다.
- **로그 전문** — 8.2절 5단계의 로그는 Vercel 대시보드에 이미 잘 나와 있습니다. 그대로 우리 화면에 옮겨 봐야 폰에서는 읽지도 못하고, 화면만 글자로 뒤덮입니다. 로그는 원인이 안 잡혔을 때 노트북으로 보러 가는 것으로 남겨 둡니다.
- **실시간 그래프** — 그럴듯해 보이지만 해석이 필요합니다. 해석이 필요한 순간 3초 판정은 실패합니다.

이 세 가지를 빼는 기준은 하나입니다. **폰 화면에서 3초 만에 "괜찮다 / 안 괜찮다"를 말해 주지 못하는 것은 넣지 않습니다.**
