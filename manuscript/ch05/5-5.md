# 5.5 트러블슈팅 — 배포는 됐는데 에러 페이지가 뜰 때

로컬에선 잘 되던 게 배포하면 안 되는 경우가 있습니다. 당황할 것 없습니다. 서버에서 무슨 일이 있었는지는 전부 **로그(log)**라는 기록에 남아 있고, 우리 일은 그 기록을 Claude에게 배달하는 것뿐입니다.

## 로그는 두 종류입니다

**① 빌드 로그** — 코드를 조립(빌드)하다 실패한 기록. 대시보드에서 실패한(빨간) 배포를 클릭하면 보입니다. 배포 자체가 실패했을 때 보는 곳.

**② 런타임 로그** — 조립은 됐는데 **실행 중** 터진 기록. 페이지에 500 에러류가 뜰 때 보는 곳. 프로젝트 화면의 **Logs**(또는 Runtime Logs) 탭에서, 에러가 난 시각 근처의 빨간 줄을 찾으세요.

구분법: **배포 목록에서 빨간색 = 빌드 로그 / 배포는 초록색인데 페이지가 에러 = 런타임 로그.**

## 배달 템플릿

> **Claude에게 이렇게**
>
> ```
> Vercel 배포에서 문제가 생겼어.
> - 상황: [배포 자체가 실패 / 배포는 성공인데 페이지가 500 에러]
> - 로컬(내 컴퓨터)에서는 정상 동작해.
> - 로그 전문:
> [복사한 로그]
> 원인을 설명하고 고쳐서, 커밋/push까지 해줘.
> ```

## 단골 범인 셋

**1. requirements.txt 누락** — 로컬에는 설치돼 있는데 목록에 안 적힌 부품. 로그에 `ModuleNotFoundError: No module named 'xxx'`가 보이면 이겁니다. Claude가 requirements.txt에 한 줄 추가하고 push하면 끝.

**2. 파일 경로 문제** — 로컬에서는 되던 `index.html` 읽기가 서버에서는 경로가 달라 실패하는 경우. 로그에 `FileNotFoundError`. 역시 Claude에게 로그를 주면 경로 처리를 고쳐줍니다.

**3. 파이썬 버전 차이** — 드물지만, 내 컴퓨터와 서버의 파이썬 버전이 달라 생기는 문제. 로그 + "Vercel 파이썬 버전을 명시하는 법 알려줘"로 해결.

셋 다 공통점이 보이시죠. **"내 컴퓨터에서는 되는데"는 원인이 아니라 단서**입니다. 내 컴퓨터와 서버의 환경 차이 — 그게 늘 범인이고, 로그가 늘 증거입니다.

> **이 장에서 만든 것**
>
> - `https://*.vercel.app` — 전 세계에서 열리는 내 초대장 (첫 번째 "와")
> - GitHub ↔ Vercel 자동 배포 파이프라인: push = 배포
> - 롤백이라는 안전망, 로그라는 블랙박스의 위치
>
> **비용: 여전히 0원. 카드 등록: 여전히 없음.**

그런데... 배포된 초대장을 며칠 뒤에 열어보면 이상한 일이 벌어져 있을 겁니다. 분명히 친구가 남긴 축하 메시지가 **사라져 있습니다.** 다음 장에서 이 미스터리를 파헤칩니다. 이 책에서 가장 중요한 개념이 나옵니다.
