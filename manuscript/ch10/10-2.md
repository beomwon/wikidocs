# 10.2 실습 — 다음 모임 초대장을 party.내도메인에 연결

두 번째 프로젝트를 만듭니다. 이번엔 이 책의 전 과정을 **초스피드로 복습**하는 실습이기도 합니다. 1회차 때 며칠 걸렸던 길이 이번엔 30분이면 끝납니다 — 그 속도 차이가 여러분이 배운 것의 증명입니다.

## 1단계: 새 프로젝트 생성 (3장의 복습)

3.7절의 변형 레시피에서 하나 골라, **새 폴더**에 만듭니다.

> **Claude에게**
>
> ```
> "party-invitation"이라는 새 폴더에, 3장에서 만든 것과 같은 구조의
> 초대장 프로젝트를 새로 만들어줘 (FastAPI + main.py + index.html +
> requirements.txt). 이번 주제는 [연말 파티]야. 분위기는 [네온사인 느낌].
> 방명록과 참석 여부 기능도 포함하고, 저장은 일단 메모리로.
> ```

## 2단계: GitHub 새 저장소 (4장의 복습)

> ```
> 이 프로젝트를 git 초기화하고, .gitignore 넣고,
> 내 GitHub에 "party-invitation" 저장소를 만들어서 push해줘.
> ```

프로젝트 하나 = 저장소 하나. 이제 이 문장이 자연스럽게 읽히시죠.

## 3단계: Vercel 새 프로젝트 (5장의 복습)

Vercel 대시보드 → Add New → Project → `party-invitation` Import → Deploy. 두 번째라 화면이 낯익을 겁니다. `party-invitation-어쩌구.vercel.app`이 생깁니다.

(DB가 필요하면 7장 복습으로 Neon을 하나 더 연결하면 됩니다. Neon 무료 플랜은 프로젝트 여러 개를 지원합니다. 가벼운 실습이 목적이면 메모리 저장인 채로 둬도 됩니다 — 대신 메시지가 증발한다는 걸 이제 여러분은 **알고** 있죠.)

## 4단계: 서브도메인 연결 (9장의 복습 — 그런데 훨씬 쉬움)

새 프로젝트의 Settings → Domains에서 이번엔 이렇게 입력합니다.

```
party.gildong.com
```

- **9장에서 방법 B(네임서버 위임)를 골랐다면**: 이게 끝입니다. 진짜로요. Vercel이 자기 전화번호부에 알아서 줄을 긋습니다. 커피 내리고 오면 연결돼 있습니다.
- **방법 A를 골랐다면**: Vercel이 CNAME 정답지를 보여줍니다. hosting.kr DNS 관리에서 호스트 `party`, 값은 화면의 그 주소로 CNAME 한 줄 추가 — 9.2절에서 한 것과 똑같습니다.

전파(9.5절)를 잠깐 기다리면 — `https://party.gildong.com`이 열립니다. 자물쇠도 자동으로.

## 방금 증명된 것

같은 도메인 아래에서 **서로 완전히 독립된 두 서비스**가 돌고 있습니다.

```
gildong.com          → invitation 프로젝트 (첫 초대장)
party.gildong.com    → party-invitation 프로젝트 (완전히 딴 코드, 딴 저장소)
```

한쪽을 부수든 지우든 다른 쪽은 멀쩡합니다. 프로젝트마다 이 구조를 반복하면 됩니다. **만들기 → push → Vercel Import → 서브도메인 입력.** 이게 여러분의 평생 루틴입니다.

> **자주 막히는 지점**
>
> - *"두 번째 프로젝트가 첫 번째 저장소를 덮어썼어요."* — 새 프로젝트를 **새 폴더 + 새 저장소**로 만들었는지 확인하세요. 폴더를 재활용하면 git이 한 저장소에 섞습니다. Claude에게 "이 폴더를 기존 git에서 분리해서 새 저장소로 만들어줘"라고 하면 수습됩니다.
> - *"party 서브도메인이 첫 번째 프로젝트로 열려요."* — 도메인을 엉뚱한 프로젝트의 Domains에 추가한 경우입니다. Vercel에서 도메인이 어느 프로젝트에 붙어 있는지 확인하고 옮기세요.
