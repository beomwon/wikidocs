# 2.1 API가 뭔가 — 주문서 하나로 끝내는 비유

1권 2.2절에서 프론트엔드와 백엔드를 식당의 **홀과 주방**에 비유했습니다. 손님이 보는 화면이 홀, 뒤에서 저장하고 처리하는 프로그램이 주방이었죠. 이번 권은 그 비유를 한 칸 넓힙니다.

우리 주방은 축하 메시지를 저장하는 일은 잘합니다. 그런데 전국 지도를 그리거나 내일 오후 강수확률을 아는 일은 못 합니다. 재료 자체가 우리에게 없으니까요. 이럴 때 식당은 어떻게 할까요. **옆 가게에 주문서를 보냅니다.**

![](https://static.wikidocs.net/images/page/386103/ch02-order.png)

## 주문서를 보내는 일이 API 호출입니다

**API 호출(call)** — 내 서버가 남의 서버에 주문서를 보내는 일입니다. 주문서에 적히는 건 늘 세 가지입니다.

- **무엇을** 달라는 건지 (지도 조각, 예보값)
- **어떤 조건으로** 달라는 건지 (서울 강남구, 오늘 오후 6시)
- **내가 누구인지** (2.2절에서 이야기할 키)

이 주문서를 **요청(request)**, 옆 가게가 돌려주는 결과를 **응답(response)**이라고 부릅니다. 식당 주문과 다른 점은 하나뿐입니다. 사람이 아니라 프로그램끼리, 정해진 양식으로만 주고받는다는 것.

## 응답은 JSON이라는 양식으로 옵니다

돌려받는 답은 우리가 보는 화면처럼 예쁘게 생기지 않았습니다. **JSON(제이슨)** 이라는, 프로그램이 읽기 좋게 정리된 글자 뭉치로 옵니다. 날씨 응답이라면 대충 이런 모양입니다.

```
{
  "지역": "서울",
  "하늘": "맑음",
  "기온": 24
}
```

이름표와 값이 짝지어 있을 뿐이라, 사람이 봐도 대충 읽힙니다. 실제 응답은 이보다 훨씬 길고 이름표도 암호 같지만 (6.3절에서 만납니다) 구조는 똑같습니다.

**여러분이 JSON을 직접 다룰 일은 없습니다.** 주문서를 쓰고, 답을 뜯어보고, 화면에 예쁘게 옮기는 일은 전부 Claude가 합니다. 여러분이 할 일은 "지도를 넣어줘", "날씨를 보여줘"라고 시키고 결과를 눈으로 확인하는 것입니다. 다만 나중에 에러 화면에 이 중괄호 덩어리가 튀어나왔을 때 놀라지 않으려고, 생김새만 한 번 봐 둔 겁니다.

다음 절은 주문서에 반드시 적어야 하는 세 번째 항목 — "내가 누구인지"에 해당하는 API 키 이야기입니다.
