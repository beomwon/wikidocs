# 7.5 Claude에게 시켜서 방어막 두르기

세 가지를 따로따로 시키면 서로 어긋나기 쉽습니다. 타임아웃은 붙었는데 폴백이 없어서 결국 에러가 나는 식입니다. 한 번에 시킵니다. 아래 프롬프트를 그대로 붙여넣으세요.

> **Claude에게 이렇게 시키세요**
>
> ```
> 초대장의 외부 API 연동에 타임아웃, 캐싱, 폴백을 붙여줘.
>
> [배경]
> - 이 프로젝트는 Vercel 서버리스에 배포돼 있어. 함수는 요청이
>   올 때만 잠깐 실행되고 사라져.
> - 날씨는 내 서버의 /api/weather 창구가 기상청 단기예보 API를
>   대신 호출하는 구조야. 인증키는 WEATHER_SERVICE_KEY 환경변수야.
> - 카카오맵은 브라우저에서 KAKAO_JS_KEY로 직접 불러오고 있어.
>
> [조건]
> - 기상청 호출에 4초 타임아웃을 걸어줘. 4초 안에 응답이 없으면
>   기다리지 말고 포기해.
> - 받아온 날씨 응답을 15분 동안 캐시해서 재사용해줘. 방문자가
>   몰려도 기상청에는 15분에 한 번만 물어보게 해줘.
> - 실패했을 때 초대장 본문(날짜, 장소, 방명록)은 반드시 정상적으로
>   렌더링돼야 해. 날씨 때문에 페이지 전체가 에러 나면 안 돼.
> - 날씨 폴백: 마지막으로 성공한 값이 있으면 "○시 기준"을 붙여서
>   보여주고, 그것도 없으면 "날씨 정보를 불러오지 못했습니다"를
>   조용히 표시해줘. 경고색은 쓰지 마.
> - 지도 폴백: 지도가 안 떠도 주소 텍스트와 카카오맵으로 여는 링크는
>   화면에 남아 있게 해줘. 주소는 지도 영역 바깥에 둬.
> - 실패할 때마다 실패 사유(타임아웃인지, 키 문제인지, 응답 형식
>   문제인지)를 서버 로그에 남겨줘.
> - 날씨를 마지막으로 성공적으로 받아온 시각을 기록해둬. 나중에
>   관리자 페이지에서 그 값을 읽어 쓸 거야.
>
> 다 만들면: 일부러 실패시켜서 폴백을 확인하는 방법을 알려줘.
> ```

## 프롬프트 해설

- **"함수는 요청이 올 때만 잠깐 실행되고 사라져"** — 이 한 줄이 있고 없고가 결과를 바꿉니다. 이 말이 없으면 AI는 계속 켜져 있는 서버를 가정하고, 오래 살아남는 캐시를 전제로 코드를 짭니다. 서버리스라는 사실을 알려주면 캐시가 사라질 수 있다는 전제로 짜줍니다.
- **"4초"와 "15분"** — 숫자를 우리가 정해서 줍니다. 안 주면 AI가 임의로 정하는데, 대개 우리 사정보다 넉넉하게 잡습니다. 7.2절과 7.3절에서 정한 값입니다. 취향에 따라 3초, 10분으로 바꿔도 됩니다.
- **"초대장 본문은 반드시 정상 렌더링"** — 7.4절의 원칙을 그대로 문장으로 옮긴 것입니다. 이 조건이 이 프롬프트에서 가장 중요합니다.
- **"경고색은 쓰지 마"** — 안 적으면 AI는 실패 상태를 빨간 박스로 강조하는 경향이 있습니다. 방문자는 그걸 보고 사이트가 고장 났다고 생각합니다.
- **"실패 사유를 서버 로그에 남겨줘"** — 나중에 "날씨가 안 나와요"라는 연락을 받았을 때, 원인을 짚을 근거가 됩니다. 8장에서 원인을 좁히는 순서를 다룰 때 이 로그를 씁니다.
- **"마지막 성공 시각을 기록해둬"** — 이 조건은 빼지 마세요. 9.4절 관리자 페이지의 날씨 카드가 바로 이 값을 읽어서 "정상 / 캐시로 버티는 중 / 실패"를 판정합니다. 지금 안 넣으면 9장에서 되돌아와야 합니다.

## 성공 판정

잘 되는 걸 확인하는 건 쉽습니다. 초대장을 열어서 날씨가 뜨면 됩니다. 문제는 그게 **방어막이 작동한 증거가 아니라는 것**입니다. 원래 잘 되던 거니까요.

그래서 일부러 고장 내봅니다.

1. Vercel 대시보드에서 우리 프로젝트를 엽니다.
2. `Settings` > `Environment Variables`로 들어갑니다.
3. `WEATHER_SERVICE_KEY` 값을 편집합니다. 끝에 글자 몇 개를 덧붙이거나 지워서 **일부러 틀린 키**로 만듭니다. (원래 값은 반드시 어딘가에 복사해 두세요.)
4. 저장하고, `Deployments` 탭에서 최신 배포를 다시 배포(Redeploy)합니다. 환경변수는 바꾼 뒤 재배포해야 반영됩니다.
5. 배포가 끝나면 초대장 주소를 새 탭에서 엽니다.

확인할 것은 이겁니다.

- 초대장이 **열립니다.** 흰 화면도, 에러 화면도 아닙니다.
- 날짜, 장소, 방명록이 **전부 정상입니다.**
- **날씨 자리만** 폴백으로 바뀌어 있습니다. "날씨 정보를 불러오지 못했습니다" 또는 "○시 기준" 표시입니다.

이 세 가지가 모두 맞으면 방어막이 제대로 붙은 것입니다. Vercel의 런타임 로그를 열어보면 실패 사유가 한 줄 남아 있는 것도 볼 수 있습니다.

확인이 끝났으면 **`WEATHER_SERVICE_KEY`를 원래 값으로 되돌리고 다시 배포하세요.** 이걸 잊고 넘어가면 모임 당일까지 날씨가 계속 안 나옵니다. 실제로 가장 흔한 사고입니다.

지도 쪽도 같은 방식으로 확인할 수 있습니다. 브라우저에서 지도를 못 불러오게 만드는 건 조금 번거로우니, 간단하게는 `KAKAO_JS_KEY`를 틀리게 바꿔 재배포하고 지도 자리가 회색이 됐을 때 **주소와 카카오맵 링크가 그대로 있는지**만 보면 됩니다. 이것도 확인 후 되돌립니다.

## 배포

> ```
> "외부 API 타임아웃, 캐싱, 폴백 추가"라는 메시지로 커밋하고 push해줘.
> ```

> **자주 막히는 지점**
>
> - *"키를 틀리게 바꿨는데 초대장이 아예 안 열려요."* — 폴백이 안 붙었거나, 붙었는데 날씨 실패가 페이지 렌더링까지 끌고 넘어지는 구조입니다. Claude에게 "날씨 호출이 실패해도 페이지 나머지는 정상 렌더링돼야 해. 지금은 페이지 전체가 에러 나"라고 그대로 말해주세요. 그래도 안 되면 부록 B의 수동 세팅을 따라 하세요.
> - *"AI가 타임아웃만 붙이고 캐싱이나 폴백은 안 만들었어요."* — 흔한 일입니다. 조건이 여러 개면 한두 개를 빠뜨립니다. 프롬프트의 [조건] 항목을 하나씩 짚으면서 "이 조건은 어디에 반영됐어?"라고 물어보세요. 안 됐다고 답하면 그 항목만 다시 시킵니다. 세 번 이상 시켜도 빠진다면 **부록 B**에 셋 중 무엇이 빠졌는지 확인하는 방법과, 빠진 하나만 다시 시키는 프롬프트가 정리돼 있습니다.
> - *"캐시가 되는 건지 모르겠어요."* — 서버리스에서는 백엔드가 자주 새로 깨어나서, 새로고침할 때마다 캐시가 비어 있는 것처럼 보일 수 있습니다. 정상입니다(7.3절). 판단은 새로고침이 아니라 로그로 하세요. 짧은 시간 안에 여러 번 열었을 때 기상청 호출 로그가 그 횟수보다 적게 찍히면 캐시가 동작하는 것입니다.
> - *"되돌렸는데도 날씨가 계속 안 나와요."* — 두 가지를 확인하세요. 첫째, 환경변수를 고친 뒤 **재배포**를 했는지. 둘째, 캐시에 실패 상태가 남아 있는 건 아닌지. 후자라면 15분 기다렸다가 다시 열어보면 됩니다. 그래도 안 되면 키 값 앞뒤에 공백이 섞였을 가능성이 큽니다. 5.5절로 돌아가 다시 복사해 넣으세요.

방어막을 다 둘렀습니다. 이제 초대장은 남의 서버가 흔들려도 혼자 서 있습니다. 다음 장부터는 그 흔들림을 **내가 볼 수 있게** 만드는 이야기입니다.
