# 2.5 이 그림 하나만 기억하세요

1권 2.4절에서 "친구가 초대장을 여는 3초 동안 일어나는 일"을 한 장면에 담았습니다. 그때는 등장인물이 넷이었죠. 브라우저, 서버, 데이터베이스, 그리고 그 사이의 길. 이번 권을 지나면 그 장면에 화살표가 몇 개 늘어납니다. 다시 그려 보겠습니다.

## 하객이 초대장을 여는 순간

1. 하객이 링크를 누릅니다. 브라우저가 내 주소를 열고, Vercel의 **내 서버**가 초대장 화면을 내려줍니다.
2. 화면이 그려지면서 **지도**가 필요해집니다. 이건 하객의 브라우저가 카카오에 직접 요청해서 받아 그립니다. 키는 브라우저에 있고, 도메인 등록으로 지킵니다.
3. **날씨**는 다릅니다. 브라우저는 내 서버의 `/api/weather`만 부르고, 내 서버가 인증키를 들고 기상청에 다녀와 결과만 내려줍니다. 키는 서버 밖으로 나가지 않습니다.
4. **방명록**은 1권에서 이미 만든 길입니다. 내 서버가 Neon에 저장된 메시지를 읽어 옵니다.
5. 하객이 축하 메시지를 남기면 4번 길을 거꾸로 타고 Neon에 저장됩니다.

여기까지가 2장의 요약이자, 4장부터 6장까지 실제로 만들 것의 전부입니다.

## 그리고 이 화살표들이 곧 관리자 화면입니다

이 절에서 진짜 기억해야 할 건 이겁니다. **위 그림의 화살표 하나하나가 고장 날 수 있는 지점이고, 관리자 페이지는 그 지점마다 상태등을 하나씩 달아 놓은 화면입니다.**

| 그림 속 화살표 | 고장 나면 하객이 겪는 일 | 관리자 화면의 칸 |
|---|---|---|
| 브라우저 → 내 서버 | 페이지 자체가 안 열림 | 1. 서버 |
| 내 서버 → Neon | 방명록이 텅 비거나 저장이 안 됨 | 2. 데이터베이스 |
| 브라우저 → 카카오 | 지도 자리가 회색으로 남음 | 3. 카카오맵 |
| 내 서버 → 기상청 | 날씨 위젯이 비어 보임 | 4. 날씨 |
| 하객의 방문 자체 | (고장은 아니지만 궁금한 것) | 5. 방문자 |
| 하객이 남긴 것 | (고장은 아니지만 궁금한 것) | 6. 방명록·참석 |

1권을 마쳤을 때 여러분이 확인할 수 있는 건 "사이트가 열리나"뿐이었습니다. 그래서 뭔가 이상하다는 연락을 받으면 어디부터 봐야 할지 알 수 없었습니다. 8장부터 만들 관리자 페이지는 이 표를 그대로 화면으로 옮긴 것입니다. 한 화면을 열면 여섯 칸의 색만 보고 어디가 문제인지 알 수 있게 됩니다.

> **이 장에서 배운 것**
>
> - API = 내 서버가 못 하는 일을 남의 서버에 시키는 주문서. 보내는 게 요청, 받는 게 응답.
> - 응답은 JSON이라는 양식으로 온다. 다루는 건 Claude의 일이다.
> - API 키 = 신분증이면서 계량기. 새면 남이 내 이름으로 쓰고 내 할당량이 줄어든다.
> - 지도 키는 브라우저에 내려간다(도메인 등록으로 지킴). 날씨 키는 서버 밖으로 안 나간다(서버가 대신 다녀옴).
> - 무료 할당량은 초대장 규모에서 넘길 일이 없고, 카드 등록이 없으니 요금도 나오지 않는다.
> - 화살표 하나 = 관리자 화면 카드 한 칸.

> **자주 막히는 지점**
>
> *"브라우저가 부르는 것과 서버가 부르는 것의 차이가 아직 잘 안 잡혀요."* — 지금은 그래도 괜찮습니다. 4장에서 지도를 붙이고 6장에서 날씨를 붙여 보면, 두 작업의 절차가 왜 다른지 몸으로 알게 됩니다. 그때 이 절로 돌아오세요.

이제 열쇠를 받으러 갑니다. 다음 장에서 카카오 개발자 사이트에 가입하고 지도 키를 발급받습니다.
