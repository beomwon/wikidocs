# 9.4 뭘 고를까 — 두 방법 비교

## 한눈 비교표

| | 방법 A (레코드 추가) | 방법 B (네임서버 변경) |
|---|---|---|
| 전화번호부 위치 | 호스팅케이알 | Vercel |
| 초기 작업 | 레코드 2~3줄 받아 적기 | 네임서버 주소 2줄 교체 |
| 반영 속도 | 보통 빠름 (분~시간) | 느린 편 (시간~하루+) |
| 서브도메인 추가(10장) | 그때마다 hosting.kr에서 CNAME 추가 | **Vercel에서 자동** (레코드 작업 불필요) |
| 도메인 이메일 등 다른 서비스와 병행 | 자유로움 (한 전화번호부에 같이 적으면 됨) | Vercel DNS에 직접 레코드 추가 (가능하지만 한 다리 건넘) |
| 관리 화면 | 두 곳 (소유: HK / 연결: HK) | 두 곳 (소유: HK / 연결: Vercel) |
| 돌이키기 | 레코드만 지우면 원상복구 | 네임서버 되돌리면 복구 (반영 대기 재발생) |

## 이 책의 추천

**Vercel 놀이터로 쓸 도메인이라면 방법 B**를 권합니다. 이유는 하나로 충분합니다 — 10장에서 서브도메인 놀이터를 만들 때, 방법 B는 "Vercel 프로젝트에 도메인 추가" 한 번으로 끝나지만, 방법 A는 매번 호스팅케이알에 가서 CNAME을 받아 적어야 합니다. 프로젝트를 늘려갈수록 이 차이가 커집니다.

다만 **방법 A가 나은 경우**도 분명합니다.

- 이 도메인으로 **이메일 등 다른 서비스를 이미 쓰고 있다** → A가 안전합니다 (9.3절의 주의사항).
- 도메인 관리를 한국어 화면에서 하고 싶다 → A. (Vercel DNS 관리는 영어 화면입니다)
- 일단 최소 변경으로 빨리 연결만 확인하고 싶다 → A로 시작했다가, 나중에 B로 갈아타도 됩니다. 방법은 언제든 바꿀 수 있습니다.

## 결정 요령 한 줄

> **"이 도메인은 Vercel 전용 놀이터인가?" — 그렇다면 B, 아니거나 모르겠다면 A.**

A로 시작해서 불편해지면 B로 옮기는 경로도 전혀 부끄럽지 않습니다. 실무에서도 흔한 경로입니다.

> **결정이 어려우면 Claude에게**
>
> ```
> 도메인을 Vercel에 연결하려고 해. 내 상황은 이래:
> - 도메인: [새로 삼 / 원래 쓰던 것]
> - 이 도메인으로 쓰는 다른 서비스: [없음 / 이메일 / 기타]
> - 계획: [Vercel에서 프로젝트 여러 개 운영할 예정 / 이번 하나뿐]
> DNS 레코드 방식과 네임서버 변경 방식 중 뭘 추천해? 이유도.
> ```

방법을 정했고 설정도 마쳤습니다. 그런데... 왜 아직도 안 열리죠? 다음 절 — 기다림의 과학, DNS 전파입니다.
