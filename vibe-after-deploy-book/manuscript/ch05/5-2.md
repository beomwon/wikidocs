# 5.2 기상청 단기예보 API 찾아서 활용신청

먼저 경고부터 하겠습니다. **이 장에서 가장 사고가 많이 나는 자리가 여기입니다.** 포털에서 "단기예보"를 검색하면 이름이 거의 똑같은 서비스가 여러 개 나옵니다. 그중 엉뚱한 것을 신청해 놓고 6장에서 "키는 받았는데 계속 에러가 난다"며 몇 시간을 헤매는 일이 흔합니다. 키가 잘못된 게 아니라 **다른 서비스의 키**를 들고 우리 서비스 문을 두드리고 있는 것이라 영원히 열리지 않습니다.

## 우리가 쓸 것 하나

**기상청_단기예보 ((구)_동네예보) 조회서비스, 데이터 번호 15084084.**

이름이 비슷해서 헷갈리는 것들은 이렇습니다. 전부 다른 서비스이고, 다른 키가 필요합니다.

| 이름 | 번호 | 이 책에서 |
|---|---|---|
| 기상청_단기예보 ((구)_동네예보) 조회서비스 | 15084084 | 이것을 씁니다 |
| 기상청_단기예보 통보문 조회서비스 | 15058629 | 쓰지 않습니다 |
| 기상청_단기예보 조회서비스 (기상청API허브 연계) | 15139470 | 쓰지 않습니다 |
| 기상청_중기예보 조회서비스 | 15059468 | 쓰지 않습니다 |

검색 결과에서 눈으로 고르지 말고 **번호를 확인하세요.** 가장 확실한 방법은 검색을 아예 건너뛰고 상세 페이지로 바로 가는 것입니다. [data.go.kr/data/15084084/openapi.do](https://www.data.go.kr/data/15084084/openapi.do) 로 접속하면 그 페이지가 우리가 원하는 그 서비스입니다. 즐겨찾기에 넣어 두세요. 이 장에서 몇 번 더 들르게 됩니다.

## 활용신청하기

상세 페이지에 들어가면 **`활용신청`** 버튼이 있습니다. 그것을 누르면 신청서 한 장이 나옵니다.

1. **시스템 유형 선택** — 화면의 안내에 따라 고르면 됩니다.
2. **활용목적 입력** — 무엇에 쓸 것인지 적는 칸입니다.
3. **상세기능정보 선택** — 이 서비스가 제공하는 기능 목록에서 쓸 것을 체크합니다.
4. **라이선스 표시 동의** — 동의에 체크합니다.

다 채웠으면 신청 버튼을 누릅니다. 여기까지가 전부입니다.

## 활용목적 칸에서 겁먹지 마세요

**활용목적**에서 손이 멈추는 분이 많습니다. 뭔가 그럴듯한 사업 계획을 써야 할 것 같고, 잘못 쓰면 반려당할 것 같거든요.

**심사가 없습니다.** 이 서비스는 자동승인이라(5.3절) 사람이 읽고 판단하는 절차가 없습니다. 그러니 솔직하게 쓰면 됩니다. `개인 프로젝트로 모임 초대장 웹페이지를 만드는데, 모임 장소의 날씨를 보여주려고 합니다` 정도면 충분합니다. 거창하게 지어낼 이유도 없고, 지어낸다고 뭐가 달라지지도 않습니다.

## 상세기능정보에서 이것만 확인

신청서에서 **딱 하나 신경 써야 할 곳**이 상세기능정보입니다. 목록에 기능이 여러 개 나오는데, 그중 **`getVilageFcst`(단기예보조회)** 가 체크되어 있는지 확인하세요. 우리가 6장에서 부를 것이 바로 이 기능입니다. 이게 빠지면 키를 받아도 예보를 못 가져옵니다.

나머지 기능들은 체크되어 있어도 상관없습니다. 어차피 안 쓰면 그만이고, 추가로 신청했다고 손해 보는 것도 없습니다. 판단이 서지 않으면 전부 체크해 두어도 됩니다.

> **자주 막히는 지점**
>
> - *"검색했더니 비슷한 게 너무 많아서 뭘 눌렀는지 모르겠어요."* — 상세 페이지 주소나 화면에 표시된 번호가 `15084084`인지 확인하세요. 다르면 위 주소로 다시 들어가서 신청하면 됩니다.
> - *"이미 다른 걸 신청해 버렸어요."* — 신청을 되돌릴 필요는 없습니다. 그냥 두고 `15084084`를 추가로 신청하세요. 여러 서비스를 신청해 두는 것 자체는 아무 문제가 없습니다.
> - *"`getVilageFcst`의 철자가 이상한데 오타 아닌가요?"* — 오타처럼 보이지만 저게 정확한 이름입니다. `l`이 하나입니다. 6장에서 다시 강조하겠습니다.
