# 7.3 AI에게 시켜서 방명록을 DB에 연결하기

이제 "메모리에 저장"을 "Neon에 저장"으로 바꿉니다. 이 절의 프롬프트가 이 책에서 기술적으로 가장 밀도 높은 프롬프트입니다. 그대로 붙여넣으세요.

> **🗣️ Claude에게 이렇게 시키세요**
>
> ```
> 초대장의 저장 방식을 메모리에서 PostgreSQL 데이터베이스로 바꿔줘.
>
> [배경]
> - 이 프로젝트는 Vercel 서버리스에 배포되어 있어.
> - Vercel에서 Neon(PostgreSQL)을 연결했고, 접속 주소는
>   DATABASE_URL 환경변수로 주입돼. 주소를 코드에 직접 쓰지 마.
>
> [조건]
> - SQLAlchemy 2.x와 psycopg를 사용해줘.
> - 축하 메시지와 참석 여부(RSVP)를 각각 테이블로 만들어줘.
> - 테이블이 없으면 시작할 때 자동 생성되게 해줘.
> - 서버리스 환경에 맞게 DB 연결을 관리해줘 (연결 풀 설정 등).
> - 내 컴퓨터에서 테스트할 수 있게 .env 파일에서 DATABASE_URL을
>   읽는 것도 지원해줘. .env가 .gitignore에 있는지 확인해줘.
> - 필요한 패키지를 requirements.txt에 추가해줘.
>
> 다 만들면: 로컬에서 테스트하는 방법을 알려줘.
> ```

## 프롬프트 해설

- **SQLAlchemy(에스큐엘알케미)** — 파이썬 코드로 DB를 다루게 해주는 다리 같은 도구입니다. 덕분에 SQL 문장을 직접 쓰는 일이 줄어듭니다. 표준 중의 표준이라, 나중에 어떤 파이썬+DB 자료를 봐도 이 이름이 나옵니다.
- **psycopg(사이코피지)** — 파이썬과 PostgreSQL 사이의 전화선(드라이버)입니다. 존재만 알면 됩니다.
- **"서버리스 환경에 맞게 연결 관리"** — 서버리스에서는 백엔드가 수없이 켜졌다 꺼지므로, DB 연결을 아무렇게나 하면 연결이 쌓여 DB가 힘들어합니다. 이 한 줄이 그 대비를 시키는 말입니다.
- **".env에서도 읽게"** — 배포 환경(Vercel)은 환경변수로, 내 컴퓨터는 .env 파일로. 같은 코드가 양쪽에서 도는 표준 구조입니다.

## 로컬 테스트용 열쇠 준비

내 컴퓨터에서 테스트하려면 .env에 실제 주소가 있어야 합니다. Vercel 대시보드의 Environment Variables에서 DATABASE_URL 값을 복사해, 프로젝트 폴더의 `.env` 파일에 붙여넣으세요.

```
DATABASE_URL=여기에_복사한_주소
```

(.env 파일 만들기부터 어려우면 Claude에게 "복사한 주소를 .env에 넣어줘"라고 붙여넣지 말고 — 주소는 비밀이니, "환경변수 값은 내가 직접 넣을게, .env 틀만 만들어줘"라고 하는 게 좋은 습관입니다.)

로컬 실행(`uvicorn main:app --reload`) 후 메시지를 남겨보고, **터미널을 껐다 켜도 메시지가 남아 있으면** — 연결 성공입니다. 3장에서 사라지던 그 메시지가, 이제 안 사라집니다.

## 배포

늘 하던 그대로입니다.

> ```
> "DB 연결"이라는 메시지로 커밋하고 push해줘.
> ```

> **🚧 자주 막히는 지점**
>
> - *"로컬에선 되는데 배포하면 DB 에러가 나요."* — 90%는 Vercel 쪽 환경변수 문제입니다. Vercel 대시보드에서 DATABASE_URL이 우리 프로젝트에 연결돼 있는지 확인하고, 런타임 로그 전문을 Claude에게 주세요.
> - *"could not connect / timeout 에러"* — 접속 주소 형식 문제이거나 연결 방식 문제입니다. 로그를 그대로 Claude에게. "Neon + Vercel 서버리스 조합이야"라는 맥락을 꼭 함께 주세요.
> - *"패키지 설치에서 실패해요 (psycopg 관련)"* — psycopg는 종류가 여러 개라(psycopg2, psycopg[binary] 등) 가끔 조합이 어긋납니다. 에러 전문 + "requirements.txt 내용이야"를 함께 주면 바로 잡습니다.
