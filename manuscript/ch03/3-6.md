# 3.6 빨간 에러가 떴을 때 — 뭘 복사해서 Claude에게 주는가

바이브코딩에서 실력 차이가 나는 지점은 코딩이 아니라 **에러 대처**입니다. 그리고 에러 대처의 전부는 "좋은 재료를 AI에게 주는 것"입니다. 이 절 하나면 됩니다.

## 원칙: 요약하지 말고, 통째로 준다

비개발자가 가장 많이 하는 실수는 에러를 **자기 말로 요약**해서 전하는 겁니다. "뭐가 안 된대요"라고요. AI는 점쟁이가 아니라서, 요약본으로는 못 고칩니다. 반대로 에러 원문을 통째로 주면 거의 항상 고칩니다. **에러 메시지는 여러분이 읽으라고 나오는 게 아니라, AI에게 전달하라고 나오는 것**이라고 생각하세요.

## 에러가 사는 곳은 딱 두 군데입니다

**① 터미널** — 백엔드(main.py)가 아플 때 여기에 빨간 글씨가 나옵니다. 보통 `Traceback (most recent call last):`로 시작하는 긴 글입니다. **첫 줄부터 끝까지 전부** 드래그해서 복사하세요. 마지막 한 줄만 주는 것보다 전체가 훨씬 좋습니다.

**② 브라우저 개발자 도구 (F12)** — 화면(index.html)이 아플 때는 터미널이 조용합니다. 대신 브라우저에서 **F12** 키를 눌러 **콘솔(Console)** 탭을 열면 빨간 글씨가 있습니다. (맥은 ⌘+⌥+I) 이걸 복사하세요.

간단한 구분법: **버튼을 눌러도 반응이 없다 → F12. 페이지 자체가 안 뜨거나 서버가 죽었다 → 터미널.** 헷갈리면 둘 다 보면 됩니다.

## 황금 템플릿

에러를 전달할 때 이 틀을 쓰세요. 해결 확률이 눈에 띄게 올라갑니다.

> **🗣️ 에러 전달 황금 템플릿**
>
> ```
> 에러가 났어. 상황을 알려줄게.
>
> 1. 하려던 것: [축하 메시지 남기기 버튼을 눌렀어]
> 2. 기대한 결과: [메시지가 아래 목록에 추가되는 것]
> 3. 실제 결과: [아무 반응이 없음]
> 4. 에러 메시지 전문:
> [터미널이나 F12 콘솔에서 복사한 빨간 글씨 전체]
>
> 원인을 설명해주고, 고쳐줘.
> ```

포인트는 4번만이 아니라 1~3번입니다. "하려던 것"과 "실제 결과"의 간극이 AI에게는 가장 중요한 단서입니다.

## 스크린샷도 훌륭한 재료입니다

Claude는 이미지를 읽을 수 있습니다. 글씨 복사가 어려운 상황(이상하게 깨진 화면, 복잡한 대시보드)이면 화면을 캡처해서 붙여넣고 "이 화면에서 뭐가 문제야?"라고 물어도 됩니다. 특히 5장 이후 Vercel 대시보드처럼 **처음 보는 관리 화면**에서 유용합니다.

## 그래도 안 되면: 새 대화의 힘

같은 에러로 AI와 다섯 번 이상 핑퐁을 하고 있다면, 대화가 산으로 갔을 가능성이 큽니다. 새 대화를 열고 이렇게 시작하세요.

> ```
> FastAPI로 만든 초대장 프로젝트에서 [증상]이 발생해.
> 관련 파일을 보여줄게. 처음부터 원인을 진단해줘.
> [main.py와 index.html 내용 또는 프로젝트 폴더 공유]
> ```
>
> 오래된 대화의 잘못된 가정을 버리고 새 눈으로 보게 하는, 개발자들도 쓰는 실전 기술입니다.
