# 7.2 Vercel에서 Neon 연결 — 클릭으로 끝나는 DB 준비

DB "서버"를 마련한다니 거창하게 들리지만, Vercel Marketplace 통합 덕분에 실제 작업은 카페 와이파이 연결 수준입니다. UI 문구는 바뀔 수 있으니, 화면이 다르면 캡처해서 Claude에게 — 이제 익숙하시죠.

## 연결 절차

1. Vercel 대시보드에서 우리 프로젝트(invitation)로 들어갑니다.
2. **Storage** 탭을 엽니다.
3. 데이터베이스 목록에서 **Neon**(Postgres)을 선택하고 **Create/Connect**를 누릅니다.
4. 무료 플랜(Free)을 선택하고, 지역(Region)을 고르라고 하면 **Singapore** 등 가까운 곳을 고릅니다. (친구들과 서버 사이 거리 = 속도입니다)
5. 만들어진 DB를 우리 프로젝트에 연결(Connect)합니다.

끝입니다. 방금 여러분은 24시간 돌아가는 PostgreSQL 데이터베이스의 주인이 됐습니다. 카드 등록 없이요.

## 방금 뒤에서 일어난 중요한 일: 환경변수 자동 주입

연결이 끝나면 Vercel 프로젝트의 **Settings → Environment Variables**에 뭔가 생겨 있습니다. `DATABASE_URL`이라는 이름의 값입니다.

```
DATABASE_URL = postgresql://사용자:비밀번호@어딘가.neon.tech/db이름?...
```

이게 4.4절에서 예고했던 **DB 접속 주소**입니다. 그리고 **환경변수(environment variable)**라는 개념이 여기서 등장합니다.

- 환경변수 = 코드 바깥에서, 실행 환경이 프로그램에게 건네주는 값.
- Vercel이 우리 백엔드를 깨울 때마다 "참, 네 DB 주소는 이거야"라고 귓속말로 알려주는 방식입니다.
- 코드에는 "DATABASE_URL이라는 환경변수를 읽어라"라고만 적혀 있게 됩니다. **비밀번호가 코드에(그리고 GitHub에) 존재하지 않게 되는** 구조입니다.

4.4절의 안전 수칙과 이렇게 이어집니다: 비밀은 코드에 쓰지 않는다 → 그럼 어디에? → **배포 환경에서는 환경변수로, 내 컴퓨터에서는 .env 파일로.**

## 접속 주소 다루기 규칙 (중요)

- 이 주소를 **카톡, 블로그, GitHub, AI 대화 공유 링크** 어디에도 붙여넣지 마세요. 이 한 줄이면 누구든 여러분의 DB에 들어갑니다.
- Claude에게 코드 수정을 시킬 때도 주소 자체를 줄 필요는 없습니다. "DATABASE_URL이라는 환경변수에 주소가 있어"라고만 하면 됩니다.
- 만약 유출됐다면: Neon 대시보드에서 비밀번호 재발급(reset)이 가능합니다. 4.4절의 원칙 그대로 — **교체가 먼저, 자책은 나중.**

> **자주 막히는 지점**
>
> - *"Storage 탭에 Neon이 안 보여요."* — Marketplace 구성은 종종 바뀝니다. Vercel 대시보드 상단 검색이나 Marketplace 메뉴에서 "Neon"을 찾아 진행해도 결과는 같습니다. 헤매면 화면 캡처 → Claude.
> - *"Neon 계정을 따로 만들어야 하나요?"* — Vercel 통합으로 만들면 Neon 계정·과금까지 Vercel 안에서 관리되는 방식이라 따로 가입할 필요가 없습니다. (Neon 대시보드로 넘어가 데이터를 직접 구경할 수도 있습니다 — 7.4절에서 해봅니다.)

DB는 준비됐고 열쇠(DATABASE_URL)도 백엔드에게 전달됐습니다. 이제 코드가 이 DB를 쓰도록 고쳐야죠. 물론, Claude가요.
