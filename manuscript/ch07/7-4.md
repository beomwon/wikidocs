# 7.4 두 번째 "와" — 친구가 남긴 축하 메시지가 안 사라진다

## 검증 의식

6.2절의 사건을 재현해 봅시다. 이번엔 결말이 다릅니다.

1. 배포된 초대장(`*.vercel.app`)에서 축하 메시지를 남깁니다.
2. 폰에서도 하나 남깁니다.
3. 내일 다시 열어봅니다. — **있습니다.**
4. 일주일 뒤에 열어봅니다. — **여전히 있습니다.**

백엔드는 여전히 수백 번 사라졌다 깨어났지만, 기억은 이제 Neon의 냉장고에 있으니 무사합니다. stateless의 저주가 풀렸습니다.

## 내 데이터를 눈으로 직접 보기

여러분의 데이터가 실제로 어떻게 저장돼 있는지 구경할 수 있습니다. Vercel 대시보드의 Storage에서 연결된 Neon으로 들어가면(또는 Neon 대시보드의 Tables 메뉴), 7.1절에서 그림으로 봤던 **바로 그 표**가 실물로 보입니다.

| id | name | message | created_at |
|---|---|---|---|
| 1 | 나 | 테스트 | 2026-08-02 ... |
| 2 | 나(폰) | 폰에서 남김 | 2026-08-02 ... |

이 화면은 앞으로 유용합니다. 이상한 메시지가 달리면 여기서 직접 지울 수도 있고(행 삭제), 참석자 명단을 여기서 확인할 수도 있습니다. 말하자면 **관리자 화면을 공짜로 얻은** 셈입니다.

## 지금 우리 서비스의 전체 그림 (완성형에 가까워짐)

```
[내 컴퓨터] ─push→ [GitHub] ─자동→ [Vercel]
                                     ├─ index.html (화면)
                                     └─ main.py (백엔드, 서버리스)
                                           ↕ DATABASE_URL
                                        [Neon (PostgreSQL)]
```

2장 4절의 그림과 비교해 보세요. 도메인만 빼고 전부 갖췄습니다.

## 남은 아쉬움 하나

이제 이 초대장은 기능적으로 완성입니다. 그런데 친구에게 보내려니 주소가...

```
https://invitation-git-main-abcd123.vercel.app
```

청첩장이 이 주소면 받는 분들이 스팸인 줄 알 겁니다. 다음 장에서 이 주소를 **내 이름을 건 진짜 도메인**으로 바꿉니다. 이 책의 마지막 큰 산이자, 이 책이 다른 책과 가장 달라지는 부분입니다.

> **이 장에서 만든 것**
>
> - Neon 무료 PostgreSQL 데이터베이스 (Vercel Marketplace 통합, 카드 등록 없음)
> - DATABASE_URL 환경변수 구조 — 비밀은 코드 밖에 (배포: 환경변수 / 로컬: .env)
> - SQLAlchemy + psycopg로 DB에 저장하는 백엔드 — **메시지가 영원히 남는 초대장**
> - 데이터를 눈으로 확인하는 법 (임시 관리자 화면)

> **이 장의 자주 막히는 지점 총정리**
>
> | 증상 | 1차 조치 |
> |---|---|
> | 로컬 OK, 배포하면 DB 에러 | Vercel 환경변수 연결 확인 → 런타임 로그를 Claude에게 |
> | connect/timeout 에러 | 로그 + "Neon+Vercel 서버리스 조합" 맥락을 Claude에게 |
> | 접속 주소를 어디 붙여넣었다 | Neon에서 비밀번호 재발급 먼저 |
> | 첫 접속이 유난히 느림 | 콜드 스타트(6.3) + Neon도 잠에서 깸. 수 초면 정상 |
