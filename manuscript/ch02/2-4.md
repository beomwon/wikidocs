# 2.4 이 그림 하나만 기억하세요

지금까지 나온 용어를 전부 한 장면에 넣어 보겠습니다. **친구가 여러분의 초대장을 여는 3초 동안 일어나는 일**입니다.

```
친구의 폰 (브라우저)
   │
   │ ① "invite.gildong.com이 어디야?"
   ▼
DNS (전화번호부) ──── "그 주소는 Vercel 서버야. IP는 76.76.xx.xx"
   │
   │ ② "초대장 페이지 줘" (HTTPS로 암호화 🔒)
   ▼
서버 (Vercel, 클라우드)
   ├─ 프론트엔드 ──── 초대장 화면(HTML/CSS)을 친구 폰으로 전송
   └─ 백엔드 (FastAPI)
         │
         │ ③ "저장된 축하 메시지 목록 줘" (API)
         ▼
      데이터베이스 (Neon) ──── "여기, 철수와 영희가 남긴 메시지야"
```

친구 화면에는 초대장과 함께 쌓인 축하 메시지가 뜹니다. 친구가 새 메시지를 남기면 같은 길을 거꾸로 타고 데이터베이스에 저장됩니다.

## 이 그림에서 우리가 준비할 것

| 그림 속 등장인물 | 우리가 할 일 | 장 |
|---|---|---|
| 프론트엔드 + 백엔드 | AI에게 시켜서 만든다 | 3장 |
| (코드 보관소: GitHub) | 만든 코드를 올린다 | 4장 |
| 서버 (Vercel) | 가입하고 GitHub과 연결한다 | 5장 |
| 데이터베이스 (Neon) | 클릭 몇 번으로 연결한다 | 7장 |
| 도메인 + DNS | 사서, 전화번호부에 등록한다 | 8~9장 |
| HTTPS | **할 일 없음 (자동)** | 9장 |

그림에 GitHub이 없는 게 눈에 띄시나요? GitHub은 친구가 접속할 때는 등장하지 않습니다. GitHub은 **우리가 코드를 서버로 보내는 통로**입니다. 무대 뒤 소품실이라고 생각하세요. 4장에서 만납니다.

> **📦 이 장에서 배운 것**
>
> - 서버 = 항상 켜져 있는 응답 담당 컴퓨터. 우리는 Vercel에서 무료로 빌린다.
> - 프론트엔드 = 보이는 화면 / 백엔드 = 뒤에서 저장·처리 / API = 둘 사이의 창구
> - 도메인 = 사람용 주소, DNS = 이름→IP 전화번호부, HTTPS = 자동으로 채워지는 자물쇠
> - 외울 필요 없음. 모르는 단어가 나오면 이 장으로 돌아올 것.

> **🚧 자주 막히는 지점**
>
> *"용어가 아직도 헷갈려요."* — 정상입니다. 이 장은 지도를 미리 본 것뿐이고, 진짜 이해는 3장부터 직접 겪으면서 옵니다. "저번에 사전에서 봤던 단어네" 정도면 충분히 성공입니다.
